# Recover after compaction or truncation

Compaction replaces earlier context with a summary. Recover when your context holds a summary of earlier work or a truncation notice, before any action other than reading files. A write anywhere, a command that measures or tests, a commit, a spawn, and a reply all wait for recovery. Finish each recovery step below before the next one.

1. **Find the step.** The worklist's opening item names the playbook path, start commit, route, and endpoint, and the item in progress is the current step. Use the task record or resume note when no worklist came back.
2. **Count what came back.** A file is in context when its whole text appears after the summary, as a skill the harness attached again does. Read the [poteto-mode entry](../SKILL.md) in full when it is not. Recovery is not a resume: leave the [task triggers](task-triggers.md) unread until the next invocation, resume, or task scope change.
3. **Print the current step.** Run `python3 "<this skill's base directory>/scripts/plan.py" <file-stem> --step <n> --route <route> --harness <claude-code|codex|grok|hermes|other>` and apply its text. `<file-stem>` is the playbook file name without `.md`. On the lightweight route an item's number is not a step number, so print each step number in the item's parentheses. The print stands in for the whole playbook, so leave the playbook file unread. If the script cannot run, read the playbook file instead.
4. **Reload skills before their actions.** A skill loaded before the summary is gone unless its whole text came back. Load each skill the step names for its own work whose whole text is not after the summary. The print also lists the route's gates. Load a gate's skill when you reach the action it gates, not during recovery. A skill a task trigger had you load for the work in progress, such as `verify-commands` before a completion check, is gone too. Load it again before the next action it governs.
5. **Reconcile.** Keep completed items and existing grants as the worklist records them. Rerun a check the step requires instead of trusting a remembered result. Continue the same task without a new pause for the user.

A read that comes back cut or reports truncation is unfinished: read the missing part before acting. If a file stays unavailable, report its exact path and hold only the actions that need it. Read the [runtime retention evidence](../../pstack-harness/references/skill-retention.md) when retention or restoration affects a decision.
