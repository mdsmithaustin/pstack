# Gated publish

Read this reference in full when the repository is gated by no-mistakes, as **Gated publish** in [Opening a PR](../playbooks/opening-a-pr.md) defines. It replaces that playbook's push, rebase, PR creation, and retarget steps. The forge, body format, and title rules it names are in that playbook.

**Gated publish.** Resolve the publish path with the forge, before the first push.

- When `NO_MISTAKES_GATE` is set, you are a no-mistakes pipeline step. Never push, open a PR, or start a run.
- When `SANDBOX_NAME` is set, you run in a sandbox clone, which has no `no-mistakes` remote. When your brief says the repository is gated, or the repository commits `.no-mistakes.yaml`, commit on a feature branch and never push. Report the branch, the head SHA, and that a gated publish is needed. The host fetches the branch from its `sandbox-<name>` remote and publishes it.
- Otherwise the repository is gated when `git remote get-url no-mistakes` succeeds and `no-mistakes axi` prints no `error:`. When the remote exists but `no-mistakes axi` prints `repo not initialized`, stop and report it. On a case-insensitive disk, the likely cause is that `init` ran from a path spelled differently from the main checkout's path, the parent of the directory that `git rev-parse --path-format=absolute --git-common-dir` prints. The fix is to re-run `no-mistakes init` from that exact path. When the remote exists and `no-mistakes axi` prints any other `error:`, the gate is broken. Stop and report the error. When the repository commits `.no-mistakes.yaml` but has no `no-mistakes` remote, stop and report that `no-mistakes init` must run from the main checkout's path, the parent of the directory that `git rev-parse --path-format=absolute --git-common-dir` prints.
- When you launch a sandboxed agent on a gated repository, say in its brief that the repository is gated.

In a gated repository, the gate owns every write to the push target and every PR it opens. These rules override every push, rebase, PR creation, and retarget in other playbooks, which apply only to ungated repositories. When the no-mistakes skill is installed, read it and follow its run, gate, and `branch_sync` rules. Otherwise use `no-mistakes axi --help`.

- Never run `git push` or `git push --force-with-lease` to the push target. Publish a branch and open its PR with `no-mistakes axi run --intent-file <file> --no-publish-intent`. Write the user's goal and decisions into the intent file. For a stacked child, add `--base-branch <parent-branch>`. To reattach after a wait, run `no-mistakes axi run` with no intent.
- For a new run that changes behavior or a public workflow, check `no-mistakes axi run --help` for `--verification-plan`. When supported, save the plan outside the tracked tree and add `--verification-plan <file>` to the launch. Reuse the worklist's verification cases, commands, expected results, and evidence paths. Keep the plan separate from the user's intent. Check that `no-mistakes axi status` reports the captured plan. Reattach without the flag. For a new run, check whether it captured a plan and report any gap.
- Never create or retarget the PR with a forge CLI or a built-in PR tool.
- Never rebase a published branch by hand. Leave conflicts to the live CI monitor. After a terminal outcome, or once the monitor has stopped, restack or retarget with `no-mistakes rerun --base-branch <new-base>`. For merge preparation with a residual monitor, follow **Gated merge preparation** below.
- Push work-in-progress snapshots only to `refs/pstack/wip/<branch>` on origin. When the repository's AGENTS.md, CLAUDE.md, or CONTRIBUTING names a branch or ref convention for agent work, use that convention. When the remote rejects the ref, keep snapshots local and record why. Do not retry under another name. Delete the snapshot ref after the PR merges, following **Snapshot cleanup** below.
- Before any local commit or `rerun` on a published branch, read `branch_sync` and follow its `next_action`. Commit only when it allows a commit.
- In an attended run, relay an `ask-user` finding verbatim to the user, or from a subagent to its parent. Never pass `--yes`.
- In an unattended run, as defined in [unattended runs](../references/unattended.md), check before each `axi run` or `axi respond` whether the user or the matched playbook reserves a decision for the operator that the run could reach. A reachable Test step always reserves exception approval for the operator. Omit `--yes` whenever Test can be reached, including reattachment and responses before Test. An exhausted Test fix round can become an exception approval under `--yes`. Do not skip Test to enable unattended driving. If no reserved decision is reachable, pass `--yes`. Otherwise drive permitted actions without `--yes`, and leave any operator-reserved decision parked. A Test exception needs the operator's approval of the specific gap, even after a fix round. List each `ask-user` finding that the run fixed, verbatim, in the final report. If the run still parks under `--yes`, do not wait for an answer. Record the finding verbatim, leave the run parked, and report the run as blocked.
- While a run is active, do not review its fix commits yourself and do not add findings to it. The gate owns that review.
- Write the intent file as plain prose. Remove every `$skill` and `/skill` mention from it, because the gate's agent loads each mentioned skill.
- When `no-mistakes doctor` fails or the gate cannot run, stop and report. Publish around the gate only when the user said "bypass no-mistakes" in this session.
- Before the first run, check whether the repository config selects `pr.template`. A template file alone does not select no-mistakes template mode. For setup, follow the [PR template instructions](../../setup-pstack/references/pr-template.md). The template path and bytes must already be on the trusted default branch to affect the run. When setup is pending, retain the selected body format for post-run finalization.
- After each run that creates or updates a PR, read its live body. Check the title against **Titles**, restore the selected **Body format**, and check every author claim against the PR's full diff at the current head. Correct the title and author text with the resolved forge. Preserve the generated evidence appendix, ownership markers, and attestation byte for byte; put author additions outside it. Read the PR back and verify the selected sections and unchanged generated evidence before reporting merge-ready. A later generic run can overwrite author sections again, so repeat this check after every publication until template mode is active. The squash body comes from `merge-gate --body-file` in `playbooks/shipping.md`.
- `axi run` and `axi respond` block for up to 8 minutes. Give each call a tool timeout of 10 minutes. After `rerun` starts a new run, drive that run with `no-mistakes axi run` (reattach) and `axi respond` until it reaches an outcome.

**Snapshot cleanup.** Use only the already owned snapshot ref for the merged PR. Read it with `git ls-remote --refs <remote> <full-owned-ref>`. Check the exit status and match the returned full ref exactly. A successful read with no match means cleanup is done. A failed read, unknown ownership, unexpected ref, or changed object holds cleanup. `<expected-oid>` is the commit this owner last successfully pushed to the exact owned snapshot ref, established from that successful push operation or its existing evidence. Compare the freshly read object to that independently known commit. A fresh remote read or ref name alone establishes no ownership. If this owner cannot establish its own successful push and object, hold cleanup. Validate every target before the batch's first deletion. For a matching target, use `git push --force-with-lease=<full-owned-ref>:<expected-oid> <remote> :<full-owned-ref>`. Inspect each result before dependent writes. Stop on failure, report each target's observed effect, and refresh reads before retrying. Preserve successful earlier effects in that report. This grants no PR-branch deletion authority.

**Gated merge preparation.** Use `rerun` after a terminal outcome or once the monitor has stopped. A residual monitor after completed `checks-passed` validation also permits a full merge-preparation rerun when all these conditions hold:

- No validation gate remains unresolved, and no validation or fix agent is active.
- The caller worktree is clean, and its head equals the head the gate selects for `rerun`.
- The selected head retains every prior gate fix. The rerun retains the accepted user intent.
- The installed command refuses a clean caller head mismatch before supersession, supports same-branch supersession, and preserves the accepted explicit intent, closing references, existing open PR identity, prior `--no-publish-intent` decision, branch custody, and every prior gate fix.

While a run or its monitor remains live and the completed-validation prerequisites above do not hold, leave the branch to the pipeline, report the needed rerun, and hold.

For this completed-validation case, this pstack rule replaces guidance that requires the residual monitor to stop. Continue following the installed tool's active-gate and custody rules. Inspect current AXI status and `branch_sync` before acting. Follow an offered custody synchronization before checking head equality. This exception permits only the supported full rerun between completed validation rounds. It never permits local commits while the pipeline owns the branch or a rerun to evade a finding or approval gate. Preserve existing exceptions and skips as evidence, and retain all hard gates and countersigns. Do not add a skip or override to make merge preparation pass.

Preserve an exception as history, then check its actual human authority and approved gap before applying it now. History does not extend approval to added scenarios, failed operations, changed relevant instructions, or changed proof obligations. Missing authority remains a gap. A source annotation change alone is not a change to authoritative intent content. Before fresh validation, restore its required verification inputs through supported controls and verify that their readable contents match the intended inputs. Absent, unreadable, or mismatched inputs remain gaps. Report any external recovery as external evidence, not native inheritance.

Record the old run ID before `rerun`. After it starts the replacement, inspect the old run with `no-mistakes axi status --run <old-run-id>`. The replacement may already be executing when `rerun` returns. Require positive terminal confirmation before further owner actions or a readiness claim. A cancellation request, elapsed wait, or replacement run ID alone is insufficient. If the old run remains active or its state is unknown, hold and report it. Confirm that the replacement preserves the accepted explicit intent, closing references, existing open PR identity, prior `--no-publish-intent` decision, branch custody, and every prior gate fix. Drive fresh validation and CI on the replacement head. Require clean new validation for a clean merge-ready claim. Keep prior exceptions in the history, then recheck the independent verdict and merge authorization. Never substitute a manual abort, rebase, force-push, or monitor-timeout edit for this protocol.
