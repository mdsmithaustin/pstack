### Research

Use for external, domain, or dependency questions whose answer informs a decision. For current code behavior, use [Investigation](investigation.md). For historical motivation, use the **why** skill.

1. **Frame the decision.** Name the question, required freshness, what evidence would answer it, and when to stop. Answer a single lookup directly. Split independent domains through the **swarm** skill only when separate readers would help.
2. **Inspect sources.** Read primary sources before relying on summaries. Check the relevant version, date, and conditions. Cite each material claim where it appears and state limits that could change the decision. Count independent observations, not pages that repeat one origin.
3. **Challenge the conclusion.** Seek evidence that could overturn it. Preserve contradictions and unknowns using the confidence and contradiction guidance in [Why's epistemics reference](../../why/references/epistemics.md). A failed lookup or missing metadata does not establish that a capability is absent. Support a negative claim with an explicit statement or a check that could disprove it, and name its scope.
4. **Reconcile and stop.** Compare findings against the framed question. Resolve conflicts where the evidence permits. Report any that remain. Stop when the evidence answers the decision or further progress needs unavailable evidence. Name the remaining gap and what would resolve it.
5. **Write for the decision.** Give the answer or recommendation, supporting sources, tradeoffs, and material uncertainties. Keep facts distinct from inference. Apply the **unslop** skill. Save a cited Markdown brief when later work needs it. Use the requested path, then the repository's established research directory. If neither exists, create `docs/research/<topic>.md` in the workspace.

No PR for the research answer itself.

**Reply:** the decision, evidence, limits, and brief path when saved.
