### Bug fix

**You own this task. Plan, review, verify.** Delegate investigation and the fix to subagents, stay in the lead. Each step opens with the outcome that must hold before the next step starts. Be scientific. Every shipped line traces to runtime evidence. Belt-and-suspenders that "might help" is a hypothesis, not a fix. It does not ship. When evidence refutes a hypothesis, revert what it motivated. The smallest change the evidence justifies ships, nothing more.

1. **Reproduced.** The defect fires on the matching surface, under your control, on demand. Reproduce it yourself on the matching surface via the control skill required by the [task triggers](../references/task-triggers.md), even when a debug or instrumentation protocol says to ask the user to reproduce. Ask the user only with a stated, specific reason the control surface cannot reach the target, and only after driving it as far as it goes. If it won't reproduce directly, synthesize the trigger, tighten conditions, or instrument until it fires.
2. **Root-caused.** One mechanism explains the symptom, and runtime evidence confirms it. Before reading source yourself, spawn two subagents in one message: the `how` skill's explainer over the affected subsystem, and a **why** skill investigator over its regression history. Reproduce while they run. Form the candidate hypotheses from their reports, then rule them out until one survives. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, eliminate. When program state is unclear, add instrumentation or logging and read it as the code runs. Don't guess. For a long or stubborn hunt, follow the [loop procedure](../../pstack-harness/references/loops.md) to drive it with your CLI's loop mechanism. Confirm the surviving *mechanism* with runtime evidence before planning the repair.
3. **Repaired.** The original repro passes, and the change is the smallest one the evidence justifies. Plan the fix. When runtime evidence confirms the root cause and identifies one localized repair, go straight to the failing reproducer, then repair it. This applies even across a function boundary. If design choices or repair scope remain unresolved, call the Skill tool with `architect` first. Once runtime evidence confirms the mechanism, land the root-cause repair before optional diagnostics or typed errors. Count only a repair that passes the original repro as the fix. Keep instrumentation needed to confirm or verify the mechanism in the necessary order. Delegate implementation to a subagent on the `bug-fix` role with a specific scope. Call the Skill tool with `pstack-harness`, then follow its **Spawn a role** section to resolve the role. Disjoint file sets get one delegate each in one message. A follow-up after review is a fresh delegate with consolidated scope, never a resume.
4. **Proven.** The repro passes on the same surface, and each neighboring state the fix touches is named with its observed result. Before claiming adjacent behavior is preserved, exercise the neighboring states the fix touches, including partial, foreign, and mixed states where applicable. Mark untested states as proof gaps and limit the claim to what ran. "Inconclusive" or wrong-surface is not a pass. Flag it. Unit tests show branch behavior, not bug absence.
5. **Landed.** The failing repro lands before the fix in git history. Stage the commits so the failing repro lands before the fix in git history. When the bug has a cheap local test path, call the Skill tool with `poteto-tdd` for the failing-test-first cadence. Skip it when the test would be expensive, integration-heavy, or unclear. This is the canonical **principle-sequence-verifiable-units** skill, the failing test first and the fix on top.
6. **Published.** The branch is where the team reviews changes. Run **Opening a PR**. If the repository has no remote, mark this step `skipped: <reason>`.

**Reply:** what was broken, root cause, fix, how you verified. Paste failing-then-passing repro output verbatim.
