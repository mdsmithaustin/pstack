### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work or kept files.

The audit script requires `python3`, `rg`, and `jq` on Linux and macOS.

1. Snapshot and audit. Record `df -h /`, then run `../scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at a tool-managed path like `.claude/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, kept files, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `wip:N` also counts each file flagged skip-worktree or assume-unchanged that is present on disk, since `git status` hides edits to those. `kept:N` counts untracked paths and ignored paths except known build caches. Cache detection uses the last path component and the fixed list in `is_build_cache` in [the audit script](../scripts/worktree-audit.sh), such as `node_modules` or `dist`. Untracked paths are kept even when their names match that list. A decision trail, saved eval runs, and notes count as kept. A nested git checkout, such as a populated submodule, also counts as a kept path because the outer repository does not report its ignored files. A checkout under an already reported kept directory is covered by that directory, without another count or line. A checkout under an ignored build-cache directory still counts, such as a pip editable install in `.venv/src/<pkg>`. The audit lists each kept path on a `# kept:` line after the sorted nine-column table. The list is not capped. `DIRTY` reads `clean`, `wip:N`, `kept:N`, or `wip:N,kept:M`. Kept paths alone get bucket `hold-kept`; when tracked edits also exist, `hold-wip` wins. Show the list and get a decision on each path. `unreadable` means `git status`, `git ls-files`, or the scan for nested checkouts failed there, so the audit cannot see what the worktree holds. Its bucket is `hold-kept`. Treat it as `kept` until a re-run reads it. When the path no longer exists, `git worktree list` marks it `prunable` and nothing is left to lose, so `git worktree prune` clears it. Per Autonomy, clean and merged and not-in-use proceeds. `wip`, `kept`, and in-use pause.
5. Prune the confirmed set. Remove a worktree only when its `DIRTY` reads `clean`. `git worktree remove` deletes ignored files even without `--force`, so never run it or `rm -rf` on any other row. Never remove an `unreadable` row. For a `kept:` row, check each `# kept:` path with `find <path> -name .git -print -quit` first. A hit means the path is or holds a nested checkout. A submodule's repository can live in the worktree's admin directory, which removal deletes, so moving the checkout out does not save its commits. Never move a nested checkout. Push or bundle its refs and then delete it only when the user names it disposable, or leave the worktree in place. Move any other kept path only to a location the user names, or delete one the user named as disposable. Then re-run the audit. A row that now shows `wip:` goes back to step 4. Repeat until `DIRTY` reads `clean`. Then, per path, `git worktree remove --force <path>`. If the dir survives on build caches, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, your editor's app-support caches (for Cursor/VS Code under `~/Library/Application Support/<editor>`: `state.vscdb.backup`, and `snapshots/roots/<root>` where a `<root>` named for a folder you opened as a workspace balloons), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, uncommitted work, or kept files).
