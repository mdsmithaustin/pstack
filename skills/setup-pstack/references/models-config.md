# The models config

`~/.agents/pstack-models.md` (user) and `.agents/pstack-models.md` (workspace) map each pstack role to a model and a reasoning effort. setup-pstack writes and lints them. Agents read them only through the resolver, which applies the rules below:

```sh
python3 "${PSTACK_SKILLS_ROOT:?}/setup-pstack/scripts/check-models-config.py" --resolve --harness codex feature
```

Failure signal: nonzero exit. It prints one JSON line per arm with `role`, `arm`, `model`, `effort`, `source`, and `notes` when it substituted a value or rule 8 applies. Run it from the project root or pass `--project <root>`. With no roles it prints every role.

## Grammar

- A role line is `role: entry`, or `role, role: entry` to bind several roles at once. `reflect judgment, divergent, synthesizer` expands the bare labels to `reflect divergent` and `reflect synthesizer`.
- An entry is `model` or `model@effort`. Efforts are `none`, `low`, `medium`, `high`, `xhigh`, `max`, and `ultra`, which is Codex's maximum reasoning with automatic task delegation. The lint rejects an effort a known model cannot take, such as `none` on `gpt-6.1-sol`, `gpt-6.1-terra`, `gpt-6-astra`, `gpt-6-sol`, or `gpt-6-luna`, or `ultra` on `gpt-6-luna`, because Codex's `spawn_agent` rejects both. A gpt-6 model outside that list, such as `gpt-6.1-luna`, is checked only at resolve time, against Codex's model list.
- `inherit-parent` and `auto`, with or without `@effort`, run the arm on the parent chat model.
- Panel roles take a comma list, one arm per entry: `arena runners`, `arena cross-judge pool`, `architect runners`, and `interrogate reviewers`.
- A `## codex`, `## claude-code`, `## grok`, or `## hermes` header starts a section whose lines apply to that CLI only. Lines above any header are flat lines and apply everywhere. Put a CLI's own slug, such as `gpt-6-sol` or `grok-4.7`, under that CLI's section, because Codex, Hermes, and Grok Build each accept any model name from a flat line.
- `trail reviewer` runs the show-me-your-work reviewer and every independent verdict and review, including the audit lanes the **swarm** skill gives it. Resolve it with `--work-model '<model>@<effort>'` and the resolver moves the review off the model that did the work when the config allows another model in its family and `trail reviewer step` is not `off`, per rule 7. `default` is the entry for a spawn whose skill names no role, and ships as `inherit-parent`.
- `trail reviewer step: off` pins the reviewer, per rule 7. It is a setting, not a role. It takes `on` or `off` and defaults to `on`. It can appear once per section, cannot share a line with a role, and `--resolve` never prints it. Layers read it like a role line, so a `## codex` pin leaves Claude Code stepping, and the highest layer that names it wins.
- `routine` runs a read-only scan, parse, or watch subagent that returns a reduced finding, such as a bulk transcript read, a large artifact parse, or a watcher. Its shipped model and effort are defined in [the defaults file](../examples/pstack-models.md). A skill that names its own role keeps it.
- `# budget: <label> (<effort>)` records the budget setup-pstack last applied. Resolution never reads it.

## Resolution

1. **Layers.** The first layer that names the role wins: the workspace file's section for this CLI, the user file's section, the workspace file's flat lines, the user file's flat lines, then the shipped default in setup-pstack's `examples/pstack-models.md`, its section for this CLI before its flat lines. The shipped flat lines match every skill's inline default. A section beats a flat line in either file, so a per-repo line written for one CLI never overrides another CLI's section. The resolver prints the winning layer as `source`: `workspace ## <cli>`, `user ## <cli>`, `workspace flat`, `user flat`, `skill default ## <cli>`, or `skill default`.
2. **One line per role.** The winning line supplies the whole entry. Model and effort come from that line, and a panel's arms all come from it. An unsuffixed line never borrows an effort from another file.
3. **Usable values.** Claude Code takes the aliases `fable`, `opus`, `sonnet`, and `haiku`, and the efforts `low` through `max`. Codex, Hermes, and Grok Build take any other model name. Codex and Hermes take every effort the model takes, and Grok Build takes `low` through `xhigh`. A model the CLI cannot use becomes `inherit-parent`. An effort the CLI or the model cannot use is dropped, and the effort policy fills it as if the line wrote none.
4. **Alias translation.** On Codex and Grok Build a Claude alias translates instead of inheriting. Codex maps `fable` to `gpt-6-sol@max`, `opus` to `gpt-6-sol@xhigh`, `sonnet` to `gpt-6-sol@high`, and `haiku` to `gpt-6-luna@high`, and the translated effort applies only when the line wrote none. Grok Build maps every alias to `grok-4.7` and keeps the line's own effort. Hermes has no translation, so an alias there is `inherit-parent`.
5. **Effort policy.** A line without a usable effort gets no fill on Claude Code and Grok Build. On Grok Build the arm runs at the session effort. On Claude Code it runs at the session effort when its model is the session's model, and otherwise at the level Claude Code keeps for that model or the model's default, measured on 2.1.322, so write an `@effort` to pin it. On Codex and Hermes a spawn that names a model and no effort gets that model's default effort, so the policy fills it: `xhigh` for `hardest tasks`, `judgment and prose`, `bug-fix`, `perf-issue`, `hillclimb`, `how explainer`, `why synthesizer`, `reflect judgment`, `reflect divergent`, `reflect synthesizer`, `arena cross-judge pool`, `architect runners`, and `trail reviewer`, and `high` for every other role. A line whose model is `inherit-parent` gets no fill, because a full-history fork inherits the parent's effort. Nothing in the policy produces `max` or `ultra`. Those come only from a written suffix, the translation of `fable`, or an explicit escalation in the task. On Hermes the default `delegate_task` has no per-task model or effort field, so a resolved value reaches a child only through `hermes -z` or a field the live schema lists, and the [Hermes adapter](../../pstack-harness/references/hermes.md) says how to report an arm that inherits.
6. **Codex's model list.** On Codex the resolver reads the model list Codex keeps at `$CODEX_HOME/models_cache.json`, the catalog `codex debug models` prints. `spawn_agent` accepts only the efforts that list gives a model, so the resolver drops any other effort with a note and the effort policy fills it. When the list lacks the policy's floor too, the arm runs at the model's highest listed effort below the floor, or at its lowest listed effort when none is below, with a note. A `gpt-6-<tier>` or `gpt-6.1-<tier>` model runs as the newest of the two that the list carries with the line's effort among its levels, so the written effort drops only when neither release takes it. After an effort fill, the same pick runs with the filled effort. So `gpt-6-sol@high` runs as `gpt-6.1-sol@high`, and `gpt-6.1-luna` runs as `gpt-6-luna` on an account that lacks it. Without a readable list the lint's table decides the efforts and the model stays as written. A note names each swap.
7. **Trail reviewer step.** `--work-model MODEL[@EFFORT]` names the model and effort that did the work, and it changes only the `trail reviewer` arm. A Claude alias translates as in rule 4. A full `claude-<alias>-...` model ID maps to its alias first on a CLI that takes or translates that alias, and stays a literal slug on Hermes. For `--work-model`, Claude aliases, `inherit-parent`, and `auto` match in any case on every CLI. Full Claude IDs match in any case where they map to aliases. Hermes preserves full IDs as literal slugs, including their case. A model name takes no provider prefix or tag, so `anthropic/claude-opus-4.7` and `qwen3:8b` are usage errors (exit 2) that say to pass the bare name. On Claude Code a work model that is not a Claude alias, a `claude-<alias>-...` ID, `auto`, or `inherit-parent` is a usage error (exit 2). On another CLI a work model it cannot use adds a note to the `trail reviewer` arm and applies no step. An `inherit-parent` or `auto` work model names no model, so on every CLI the arm prints as resolved with a note to pass the session model. An arm whose model differs from the work model prints as resolved. The resolver never moves or labels an `inherit-parent` reviewer because it cannot observe the parent model. The caller discloses execution identity per pstack-harness's **Spawn a role** section. A written reviewer that differs from the work model stands. Two releases of one gpt-6 tier count as one model. On a match, the resolver takes the nearest higher tier of the work model's family, then the nearest lower tier, then the same model. The families, highest tier first, are `fable`, `opus`, `sonnet`, `haiku`; `astra`, `sol`, `terra`, `luna`; and `grok-4.7`, `grok-4.7-build-fast`. The order of the Grok pair is an assumption. A work model outside these families gets a same-model review. Only models the user's config allows count, which means every model the resolver prints for any role on this CLI. To opt out of a model, bind every role that would otherwise resolve to it, including roles supplied by shipped defaults. Leaving it out of a partial config can still allow it through an unbound role; rule 8 describes the note for that case. A step up lowers the work effort by one level and never goes below `high`. A step down or a same-model review raises it by one level. No step goes above `xhigh`. A translated alias brings its translated effort as the work effort. With no work effort after that, or `inherit-parent`, the offset applies to the reviewer's resolved effort. When a usable work effort is supplied, a stepped reviewer's effort comes from it, and the effort written on the `trail reviewer` line is ignored. Work at `high` or `xhigh` gives an `xhigh` same-model review whatever the line writes, and work at `medium` gives `high`. The result then drops to the highest level the model and CLI offer at or below it. The printed arm gains `"step": "up"`, `"down"`, or `"same-model"` and a note. A step up or down names the roles that allow the target model when one to three do, as in `stepped up to gpt-6-astra (allowed by arena cross-judge pool)`. To avoid the step, opt out of the target model as above, or pin the reviewer. `trail reviewer step: off` makes a reviewer that matches the work model stand with its resolved model and effort, in place of any step. The arm carries `"step": "same-model"` and a note, so the caller discloses the review as same-model per Spawn a role. The step never produces `max` or `ultra`, so rule 5 still holds.
8. **Warnings.** When a workspace or user file binds at least one role for this CLI, an arm that resolves from a skill default gets a note if its model appears in no flat line or matching CLI section you wrote in either file. The comparison translates aliases and counts two releases of one gpt-6 tier as one model. An `inherit-parent` arm gets no default-leak note. The note names the role and says to add a `<role>:` line. This is how a role added by a later sync would otherwise take a model you left out. A trail reviewer step onto such a model gets a note too. A panel role that resolves to fewer than two distinct models, counting two releases of one gpt-6 tier as one, gets a note on its first arm: `arena runners`, `architect runners`, and `interrogate reviewers`. Because the resolver cannot see the parent model and must never name a model wrongly, `inherit-parent` counts as its own distinct entry, so a panel mixing it with a concrete model gets no diversity note and the panel skill's rule to name the models that ran still applies. Interrogate Verify and arena Phase D require the lead to name the models before treating agreement as confirmation. Architect synthesizes through arena. `arena cross-judge pool` picks one arm and never gets this note.
9. **Same-model comparison.** `--lead-model MODEL[@EFFORT]` names the lead's session model. It takes the names `--work-model` takes, with the same case folding and usage errors. Its effort is ignored, because for this check arms that differ only in effort are one model. It changes only the first arm of `arena runners` and of `architect runners`. That arm gains `"comparison": "skip"` and a note when every arm of the role and every `arena cross-judge pool` arm is `inherit-parent` or the lead's model, counting two releases of one gpt-6 tier as one. An `inherit-parent` arm is the lead whatever the lead is, so a panel whose arms all inherit gets the field without the flag. Without the flag, every other panel resolves as it did before, and the caller reruns with the flag when the note says that the role resolves to one distinct model. When at least one arm names a model, a lead model of `auto` or `inherit-parent`, or one this CLI cannot use, gets a note and no result. Hermes compares full IDs as literal slugs, including their case, so an ID in another case gets no `skip` and the panel runs. `interrogate reviewers` never gets the field. The field covers a design comparison only. The resolver cannot see why the caller runs `arena`, so the `arena runners` note says that a review or second opinion still runs every arm. The caller acts on the field per pstack-harness's **Spawn a role** section.
