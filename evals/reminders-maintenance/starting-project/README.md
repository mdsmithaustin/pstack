# Reminder CLI

This date-only reminder tool stores recurring series in a JSON file. It supports Python 3.12 or newer and uses the standard library. Each invocation reads one JSON request from stdin and returns one JSON response on stdout, followed by a newline.

Run `python3 app.py --state /path/to/reminders.json`. The directory must exist. A missing file starts with no series. Use one process at a time. The tool does not consult the clock or send notifications. Dates must be real calendar dates in exactly `YYYY-MM-DD` format. Dates beyond year 9999 are outside its supported range.

The supported requests and responses are:

* Create with `{"action":"create","series_id":"tea","occurrence_date":"2026-01-01","cadence_days":7}`. The response is `{"series_id":"tea","status":"active","cadence_days":7}`. Repeating the same creation succeeds. Reusing the ID with another start date or cadence returns `{"error":"already_exists"}`.
* List with `{"action":"list","occurrence_date":"2026-01-15"}`. The response is `{"occurrences":[{"series_id":"tea","occurrence_date":"2026-01-01","status":"pending"},{"series_id":"tea","occurrence_date":"2026-01-08","status":"pending"},{"series_id":"tea","occurrence_date":"2026-01-15","status":"pending"}]}`. The horizon is inclusive. Records sort by date, then series ID. An empty list returns `{"occurrences":[]}`. A shorter horizon hides later records without removing them.
* Deliver with `{"action":"deliver","series_id":"tea","occurrence_date":"2026-01-08"}`. The response is `{"series_id":"tea","occurrence_date":"2026-01-08","status":"delivered"}`.
* Cancel with `{"action":"cancel","series_id":"tea","occurrence_date":"2026-01-08"}`. The response is `{"series_id":"tea","occurrence_date":"2026-01-08","status":"cancelled"}`. Cancellation affects one occurrence; later occurrences keep their original dates.
* Skip with `{"action":"skip","series_id":"tea","occurrence_date":"2026-01-08"}`. The response is `{"series_id":"tea","occurrence_date":"2026-01-08","status":"skipped"}`. Skipping closes one occurrence; later occurrences keep their original dates. Repeating the skip returns the same response.
* End a series with `{"action":"end_series","series_id":"tea","occurrence_date":"2026-01-12"}`. The response is `{"series_id":"tea","status":"ended","ended_on":"2026-01-12"}`. The inclusive boundary can be off schedule. Scheduled occurrences before it are materialized, pending records on or after it become cancelled, and new occurrences on or after it are not generated. Existing closed records remain in history.

Delivery, cancellation, and skipping can address scheduled dates before listing. Earlier scheduled dates become pending records. Repeating the same closure returns the same response. Switching a closed record to another status returns `{"error":"occurrence_closed"}`. An ended series can only be ended again at the same boundary. Creating an ended ID returns `{"error":"series_ended"}`. Closing an unrecorded occurrence on or after the boundary also returns `{"error":"series_ended"}`; a retained closed record follows the ordinary closure rules. Closed records and series boundaries persist across restarts.

Unknown fields, missing fields, unsupported actions, empty IDs, invalid dates, and invalid types return `{"error":"invalid_request"}`. The new actions do not accept `cadence_days`. Cadence must be a positive integer; booleans are invalid. A missing series returns `{"error":"missing_series"}`. A date before the series start or an off-schedule date for delivery, cancellation, or skipping returns `{"error":"invalid_occurrence"}`. An end boundary before the series start also returns `{"error":"invalid_occurrence"}`. Rejected requests exit 2 and leave state unchanged. Successful requests exit 0. The internal JSON format is private to the program. Existing CLI state files remain readable. Externally edited or malformed state files are outside the supported scope.

Run `python3 checks.py` for usage checks. Failure produces a nonzero exit; success prints the number of checks passed.
