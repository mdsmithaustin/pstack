Our host daemon reconnects twice a second forever when the server hostname stops resolving (issue #5072). On Windows with the VPN down, every attempt logs `Host tunnel disconnected: [Errno 11001] getaddrinfo failed. Reconnecting in 0.5s (recycle — prompt reconnect)` and the delay never grows. One laptop logged 122,567 attempts in about 17.7 hours and a 46 MB host log. The handshake-timeout path already backs off, so this looks like a missed case in how `omnigent/host/connect.py` picks the prompt-reconnect cadence.

Please fix it so a DNS failure takes the normal exponential backoff, and so the recycle fast path can never hammer a dead endpoint at the prompt cadence indefinitely. A genuine server recycle after a healthy connection should still reconnect promptly. Add unit coverage in `tests/host/test_connect.py`. No need to commit.
