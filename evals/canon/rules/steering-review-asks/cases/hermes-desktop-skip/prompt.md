Fix #123499. When an update is interrupted after its dependency sync, the next Hermes Desktop launch finishes it from the Desktop's own backend (`venv_sync._finish_source_update` runs `source_completion.py --finish-update --desktop` as a descendant of the Electron process). On Windows that tail's desktop build calls `_stop_desktop_processes_locking_build` in `hermes_cli/main_desktop.py`, which spares a Desktop ancestor only on POSIX. On a `win-unpacked` install it kills the very Desktop it runs under, the whole process tree dies before the completion marker and update lock are cleared, and every launch repeats it. Users are stuck in a boot loop.

The update must never stop the Desktop it is running inside, on any platform. A packaged Windows rebuild under its own Desktop can't be promoted anyway while that Desktop holds the exe lock, so skip that rebuild, let the tail finish and clear its markers, and print how the user can finish the rebuild afterwards. Leave POSIX behaviour and source builds as they are. Add regression tests for the Windows path.
