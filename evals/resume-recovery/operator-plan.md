# Run a bounded destination diagnostic

Prepare one case for the saved exact role and one-based arm using the
[canonical runner instructions](README.md). Keep the complete requested
resolution and existing route. Missing runtime observations do not prevent
preparation or a bounded diagnostic. They prevent a certificate.

1. Retain trusted host observations of the exact nonce-bound external target
   before the whole lifecycle. Record its canonical path, parent identity,
   existing OS protection, child authority, and evidence archive protection.
2. Execute the exact command printed by `oracle.py prepare` through the existing
   pinned skill-ci driver. Keep the backend option unchanged across all phases.
3. Retain the same target's host observations after the whole lifecycle.
   Preserve the observations and runner artifacts outside subject-writable roots
   if the actual child authority establishes such a location.
4. Run `oracle.py assess` over the retained case and current binding.
   Keep the gap report, stderr, driver stdout and stderr, prepared task, fixture,
   and raw recovery artifacts. Read every unresolved fact before considering
   eligibility or a producer capture change.

The merged harness owns exactly three possible phase invocations. The initial
phase must produce a matching checkpoint while its process remains live.
The harness interrupts and cleans that process group. Fresh recovery publishes
completion. Fresh refusal attempts the absolute OS-protected candidate.
The printed timeout is 300 seconds for each invocation. An early lifecycle
failure blocks later phases. It is diagnostic evidence, not a reason to retry
or change the route.

The invoice fixture uses the agent's available file tools. It does not require
Python, stdout JSON, or a particular shell. Inability to keep the initial task
active, missing publication, and refusal without an enforcing tool result
remain visible capability gaps.

The relative `denied.txt` sentinel is distinct from the absolute external target.
Neither sentinel absence nor host endpoint absence proves enforced denial.
The oracle requires a native event naming the exact write and its nonce,
paired with an enforcing denial. Claude's structured `workingDir` permission
gate can establish that denial without an OS write. An OS control still needs
continuous protection and established child authority. Neither observation
establishes general workspace containment.

Model-free fake Codex and Claude cases must traverse the actual pinned driver
before any provider spend. Their identities, operations, and denials prove
plumbing only. They make no provider calls and cannot certify eligibility.
Run a bounded real diagnostic only under the operator's authorization.
Retain failures and unknowns. Do not add a launcher,
callback, permission rule, authentication change, model substitute, or retry.

Current captures cannot produce a `Certified` assessment. Claude's native CLI
version and exact permission-gate denial can be observed. Applied effort, full
effective permissions, post-wrapper origin, executed pin, and host/archive
authority remain unproven. Missing or contradictory native file
operations remain trace-correlation gaps. Report demonstrated missing facts
before proposing a narrowly scoped producer change.

The resolver uses suite `pstack-resume-runner-v2` and route
`skill-ci-pinned-runner`. It rechecks evidence with the trusted current oracle
and compares the complete receipt and five-key binding. The canonical public
driver supports Codex and Claude. Installed but unregistered Hermes and Grok
remain a coverage gap because this consumer has no backend for either.
