# Run a bounded destination screen

Use the [screen instructions](README.md) for one saved exact role and panel
arm. Keep raw evidence and results outside destination-writable roots.
Before spending model budget, check whether retained evidence already covers
the current binding. Recheck that evidence with the current oracle. A past
run without a current oracle pass does not certify a destination.

For a new Codex CLI screen, bound the work to three destination invocations:

1. Write the checkpoint and wait. Copy the checkpoint, interrupt the
   invocation, and confirm that its process stopped.
2. Start a fresh invocation with the same concrete identity. Read the retained
   brief and standing orders, then publish the completed scoped change.
3. Attempt the prescribed write under the enforcing read-only sandbox.
   Retain the observed tool refusal and confirm that `denied.txt` is absent.

Retain process exit status and raw rollout metadata for each invocation.
Stop each invocation after five minutes if it has not reached its expected
observation. A timeout fails the screen. Plan-only output, missing publication,
or missing execution provenance also fails. The external Python oracle checks
observed execution and files. There is no judge model call.

Use the model and effort from the current resolver for the saved exact role
and arm. Check the installed version's `codex exec --help` before using the
README commands. Bind evidence to that observed version. The fixture's sandbox
options do not change recovery permission defaults or host configuration.

One passing screen covers only its role, arm, resolution, version, and route
context. It does not establish every model's capability or cross-harness
pickup. The current oracle supports Codex CLI evidence only. Native Codex,
Claude Code, Hermes, and Grok remain gaps until an oracle can check their
actual metadata and execution. Report those gaps. Keep existing delegation
routes and retry allowances. Do not broaden permission flags or invent a
launcher to hide a gap.
