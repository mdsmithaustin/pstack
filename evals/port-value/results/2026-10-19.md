# Port value results, 2026-10-19

All 36 executable stage opportunities passed in this frozen comparison. Each arm passed both stages in all six lineages. This sample provides no acceptance separation and supports no skill tuning or general causal claim.

## Study design

The run compares native Codex, minimally adapted upstream pstack, and the current Codex port. It uses three tasks, two repetitions per task and arm, and fresh initial and maintenance sessions. The tasks are `meter-intervals`, `parcel-manifest`, and `retention-schedule`. This yields 18 lineages and 36 opportunities. Two lineages run concurrently at most. The controller never retries a spent opportunity.

The plan pins upstream `1b6d44ff26d4e242f4e8f68c391e6d2f7ca16def` and current `701c9a6f09ae3b0bd56a4962ff299c21accf8690`. All arms request `gpt-6.1-sol` at `high` effort with a 240-second timeout. The template is `docker.io/library/pstack-port-value-codex:0.162.0`. The randomized block order uses seed 73129. Served model identity remains unknown in all 36 receipts.

This is a cold-start comparison with skills available for relevance-driven discovery. Requests do not explicitly activate poteto-mode. The oracles measure executable application acceptance. They do not grade requested README updates or broader task quality. Maintenance starts from the same lineage's retained initial application without acceptance feedback.

## Interpretation and next evaluation

All arms reach the executable acceptance ceiling on these three tasks. The observed current-arm body reads establish exposure to particular port skills, but the study does not isolate their effects. The sample supports neither a behavioral improvement claim nor a recommendation to tune skills from these results.

A bounded next hypothesis is whether explicit poteto-mode activation changes observable workflow execution on fresh tasks. Predeclare required exposure observations and executable acceptance criteria before that comparison. Add a separate human quality rubric if README quality or broader task quality matters. These cases are now exposed, so future behavioral tuning needs fresh held-out cases.
