Add legal holds to the retention command. A request may contain `holds`, an array that defaults to empty when absent. Each hold has a unique nonempty string `id` and a `record_ids` array of distinct IDs that all exist in records. An empty record_ids array is valid. A hold may have `released`, either null or a valid date in exact YYYY-MM-DD format. Missing released means null. Unknown fields are ignored.

A hold is active when released is null or as_of is earlier than released. It is inactive on the release date itself and afterward. An active hold keeps each named record in retain even after its deadline. Retain entries for actively held records include `holds`, an array of their active hold IDs in Python string order. Keep `until` equal to the ordinary deadline, even when it is in the past. Do not add holds to entries without active holds. Multiple active holds can name the same record. Release dates can be before closed dates and are interpreted by the same active rule.

Wrong types, duplicate hold IDs, duplicate record IDs within one hold, unknown record IDs, empty hold IDs, or invalid release dates return the existing invalid_request error for the entire request. Validate inactive holds too. Existing requests without holds keep their exact behavior and output. Update README.md to describe this addition.
