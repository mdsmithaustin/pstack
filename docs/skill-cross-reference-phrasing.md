# Skill cross-reference phrasing

Checked 2026-10-09, and 2026-11-01 for the Skill tool versus Read section, the public suites, the reliability evidence, and the recommendation. Installed hosts were Claude Code 2.1.295 and codex-cli 0.162.0 on 2026-10-09, and Claude Code 2.1.314, codex-cli 0.162.0, and Grok 1.0.70 on 2026-11-01. Codex source for the 2026-11-01 checks was read at openai/codex `cb1bc0ae` (main). Codex source was read at openai/codex `4aa94dce` (main, 2026-10-09). Earlier pstack research on 2026-09-14, kept outside the repository, reached the same Codex result at rust-v0.152.0.

## Decision

pstack needs one phrasing that a skill's body uses to make the agent load a sibling skill. The phrasing has to work on Claude Code with siblings listed name-only, and on Codex with siblings set to `allow_implicit_invocation: false`.

## Recommendation

Decided on 2026-11-01. At every site where a sibling must load, write "Call the Skill tool with `x`", with the bare skill name in code font, as in "Call the Skill tool with `no-comments`." Put it in a numbered step or a direct sentence, never in a "per" or "in" clause. Leave plain mentions (routers, "see also") as they are. Codex and Grok Build have no Skill tool for skills on disk. Hermes loads a skill with `skill_view(name)`, which this repository's grader counts as a load; how Hermes treats the phrase is unverified, because no Hermes arm ran. The planned **pstack-harness** update will map the phrase to reading `<installed skills root>/x/SKILL.md` in full on those CLIs.

The rollout is pending. Shipped skills still write "Use the **x** skill", and the **pstack-harness** skill still maps that phrase. A separate change rewrites every load site, the mapping, and the matching `PORTING.md` rule.

This decision replaces the earlier recommendation, "Use the **x** skill", which kept the mechanism out of the skill text. Two findings reversed it.

- The [2026-11-01 results record](../evals/promises/results/2026-11-01-principle-load-phrasing.md) varied the wording of one task-triggers line. On Claude Code, the lead loaded the principle before its first code write in 1 of 3 runs with "Use the" and in 3 of 3 with "Call the Skill tool with". On Codex and Grok Build, every arm run there passed 2 of 2. Those leads read the `SKILL.md` by path whatever the line said, the Skill tool arm included. The slash and path arms also reached 3 of 3 on Claude Code, and three runs per arm cannot tell the verb, the named mechanism, or its place apart. These runs show no cost on the other two CLIs.
- [Skill tool versus Read on Claude Code](#skill-tool-versus-read-on-claude-code) found that reattachment after compaction is the difference that decides. Claude Code reattaches the latest Skill invocation of each skill inside a 25,000-token budget. A `SKILL.md` loaded with Read comes back only if it ranks among the five most recently modified files the session touched, and a principle file the task never edits usually does not.

Two caveats from the research still hold. "Call the Skill tool with" is not the only wording that yields a Skill call. The `/x` arm loaded through the Skill tool in 3 of 3 runs too, but the skill reference lint bans that user syntax in shipped text. A Read is not always lost at compaction. The file can come back under the five-recent-files rule.

The [2026-10-10 results record](../evals/promises/results/2026-10-10-use-the-skill.md) measures the earlier "Use the" wording against an old-text control on Claude Code and Codex. It owns the hit rates, trace classifications, and remaining failures. Those runs support the deslop hand-off change, but do not establish a gain for every sibling-skill load point or harness.

Reasons, each with its evidence label.

1. Fact. Neither the slash nor the `$` sigil is model-side syntax. agentskills.io describes both as user syntax "that the harness intercepts". Codex parses `$name` only from `UserInput`, so a `$name` inside a loaded SKILL.md is plain text.
2. Fact. On Codex, `allow_implicit_invocation: false` hides the skill from the model's catalog. A name alone cannot resolve there. Only a file path, or a harness map that supplies the root, can reach the skill.
3. Fact. On Claude Code, the Skill tool takes "exact name from the listing, no leading slash". A `name-only` override keeps the name in that listing.
4. Inference from two independent origins (mattpocock/skills and zhupanov/larch). An explicit imperative tied to the load action fires more often than a bare mention. Both authors claim this without numbers.
5. Measured, reversing an earlier inference. This reason first said that naming "the Skill tool" literally, as Pocock does, works on Claude Code only, so the verb belonged in prose and the mapping in pstack-harness. In the 2026-11-01 runs the Claude Code load was 1 of 3 with "Use the" and 3 of 3 with "Call the Skill tool with" (and also 3 of 3 with the slash and path arms), and Codex and Grok Build leads still read the file in 2 of 2 runs each. Three runs per arm is small. "Use the" against "Call the Skill tool with" alone gives a one-sided Fisher p of 0.2. The mapping stays in pstack-harness, which will map the tool name instead of a neutral verb once the rollout lands.

### Which differences matter for trigger-site wording

1. Fact and inference. Compaction is the difference that matters (inference). Both routes can come back, but under different rules. A Skill invocation comes back by invocation recency, one per skill, inside a 25,000-token budget. A Read comes back only if the file ranks among the five most recently modified files the session touched. A principle `SKILL.md` rarely changes during a task, so edited source files will usually outrank it.
2. Inference. On Claude Code, a wording that yields a Skill call keeps the principle in context after compaction more often than a wording that yields a Read. The [2026-11-01 eval](#evidence-on-reliability) supports this split. Its arm E leads loaded the principle with Read in all 3 runs. Arms C and D loaded it with the Skill tool in all 6.
3. Fact. Base directory and framing differences do not change the choice. A Read also gives the model the file's path, and no pstack skill uses rendering or invoke-only frontmatter.
4. Inference. A path link is the only form all four hosts can follow, and on Claude Code it trades away skill re-attachment. "Call the Skill tool with" yields the Skill call on Claude Code and names a tool Codex and Grok Build do not have for file skills. Hermes is unverified.

### Codex and Grok Build

- Fact. Codex has no Skill tool for skills on disk. Its catalog prompt tells the model "For a `file` entry, open the listed path." A `skills.read` tool exists only for "`executor package` and `cloud package` entries". Source: [catalog_prompt.rs at `cb1bc0ae`](https://github.com/openai/codex/blob/cb1bc0ae4ed996c67a6e118bf79a7435f0d3f0d2/codex-rs/ext/skills/src/catalog_prompt.rs), [tools/mod.rs](https://github.com/openai/codex/blob/cb1bc0ae4ed996c67a6e118bf79a7435f0d3f0d2/codex-rs/ext/skills/src/tools/mod.rs).
- Fact. A `$name` mention in user input injects a user-role `<skill>` fragment with `<name>`, `<path>`, and the contents. A model-initiated load is a shell read whose output is an ordinary tool result. Source: [fragments.rs](https://github.com/openai/codex/blob/cb1bc0ae4ed996c67a6e118bf79a7435f0d3f0d2/codex-rs/ext/skills/src/fragments.rs).
- Inference from source, not observed. Local compaction keeps real user messages and re-injects the initial context, which holds the skill catalog and not skill bodies. Contextual fragments do not parse as user messages, and only client-authored tool outputs with no call ID are retained. So neither a `$name` injection nor a shell read of `SKILL.md` appears to be re-attached. Source: [compact.rs](https://github.com/openai/codex/blob/cb1bc0ae4ed996c67a6e118bf79a7435f0d3f0d2/codex-rs/core/src/compact.rs), [compact_retained_tool_outputs.rs](https://github.com/openai/codex/blob/cb1bc0ae4ed996c67a6e118bf79a7435f0d3f0d2/codex-rs/core/src/compact_retained_tool_outputs.rs), [event_mapping.rs](https://github.com/openai/codex/blob/cb1bc0ae4ed996c67a6e118bf79a7435f0d3f0d2/codex-rs/core/src/event_mapping.rs).
- Fact. Grok Build discovers skills, shows user-invocable ones as `/<skill-name>`, and honors `disable-model-invocation`. Its docs say `allowed-tools` "Does not grant or restrict tools", and "Grok accepts `model`, `effort`, `license`, and `compatibility` and does not apply them." Source: [Skills, plugins, and marketplaces](https://docs.x.ai/build/features/skills-plugins-marketplaces).
- Observed. In the 2026-11-01 eval, Grok 1.0.70 leads had no skill tool in their tool list, and every lead loaded the principle with `read_file`.
- Unverified. The docs do not name a model-side activation tool, its result framing, or any skill retention after compaction. Grok 1.0.70's local changelog has no entry on these.

## Evidence on reliability

- mattpocock/skills [PR #878](https://github.com/mattpocock/skills/pull/878), merged 2026-08-15. "Naming the tool directly gets a higher hit rate than dropping a bare `/name` into prose and hoping the model reads it as a command." No eval is cited.
- mattpocock/skills commit [1dab982](https://github.com/mattpocock/skills/commit/1dab98299c3b81f560026c01b7ebf55ed5d91373), fixing [#453](https://github.com/mattpocock/skills/issues/453). The explicit phrasing "made this fire more reliably in the wrong direction" against a `disable-model-invocation` target. This is the same hazard pstack's gated siblings faced before PR 185 removed the flag.
- zhupanov/larch [#168](https://github.com/zhupanov/larch/issues/168), a research report from 2026-04-19 with three agents. "Phrasing matters, but phrasing alone cannot guarantee the caller will call the sub-skill." It recommends "an explicit numbered step with an imperative verb, the tool name, and literal args", ranked below structural checks (narrow `allowed-tools`, verify the child's side effect). It reports no measured rates.
- anthropics/claude-code [#43809](https://github.com/anthropics/claude-code/issues/43809), closed. "Error: Skill cc-use-subagents cannot be used with Skill tool due to disable-model-invocation" when a subagent tries to load a gated skill.
- anthropics/claude-code [#73774](https://github.com/anthropics/claude-code/issues/73774), closed. Claude Code's system prompt tells the model to invoke the Skill tool for any `/<name>` reference, and that duplicate call errors on a gated skill.
- timharris707/skills [#302](https://github.com/timharris707/skills/issues/302). "add it without a paid eval" and "Out of scope: Measuring the hit rate."
- Thariq Shihipar of Anthropic, in [Lessons from building Claude Code: How we use skills](https://claude.dev/blog/lessons-from-building-claude-code-how-we-use-skills/): "you can just reference other skills by name, and the model will invoke them if they are installed." The page metadata gives 2026-06-03 as the publish date. No data is given.
- garrytan/gstack tells the lead to reload after compaction: "After compaction, reload current phase instructions/skill/sections" ([autoplan#L340](https://github.com/garrytan/gstack/blob/5225e35cc60312ae1b675704e7f2ffdac1ccf40e/autoplan/SKILL.md#L340)). No data is given.
- No post on sibling-skill invocation by Simon Willison, Jesse Vincent, Matt Pocock, or Hamel Husain dated after 2026-10-09 was found. Single-user tests on dev.to and one fleet's read-to-invoke ratio in get-bb/bb#4460 were found and not used, because neither shows its method.
- pstack's own 2026-11-01 eval, in the [2026-11-01 results record](../evals/promises/results/2026-11-01-principle-load-phrasing.md). On Claude Code 2.1.314 with `claude-sonnet-5-5` at effort high, five wordings of the task-triggers line for `principle-model-the-domain` ran 3 times each. "Use the" and "Load the" got the lead to load the principle before its first code write in 1 of 3 runs each. "Call the Skill tool with", "Run /principle-model-the-domain", and a relative `SKILL.md` link with "Read ... in full" each passed 3 of 3. The path arm loaded through Read, and the other two through the Skill tool. Pooled, wordings that name a load mechanism passed 9 of 9 and skill-name wordings 2 of 6 (one-sided Fisher p 0.011, pooling chosen after the results). On Codex with `gpt-6.1-sol` and on Grok Build with `grok-4.7-build`, both at effort high, "Use the" and the three mechanism wordings ran 2 times each, and all 16 runs passed. Those leads read the `SKILL.md` by path whatever the line said, "Call the Skill tool with" included. Each harness ran one model, site, and fixture.

## Contradictions

- Upstream pstack says "Delegate to other skills by path", yet its text uses bold names almost everywhere. Pocock rejects `../other-skill` links. OpenAI's own curated skills use them.
- Pocock calls "Call the Skill tool" "more harness-neutral". That holds for the sigil only. Codex has no `Skill` tool for host skills, and a hidden Codex skill cannot be reached by name at all.
- superpowers and Pocock both name the target bare, with no sigil. superpowers uses the `superpowers:` namespace that Claude Code gives plugin skills. pstack installs skills flat, so it has no namespace to use.

## Pstack state before PR 185 (measured)

This census describes the tree at f8eb694f, before PR 185 (e4968e32) dropped `disable-model-invocation` from all 47 skills. `skills/` holds 57 skills. 47 have `disable-model-invocation: true` and 47 have `allow_implicit_invocation: false`. `skills/**/*.md` contains the phrase "the **x** skill" 127 times. Where a preposition comes first, it is mostly "in" (31) or "per" (22). Imperative "Run" or "Use" comes first only 5 times. Slash forms appear in SKILL.md a handful of times (for example `/poteto-mode` 3 times).

## Unknowns

1. Precedence. Moot for pstack, because PR 185 removed the frontmatter flag and the 2026-10-10 runs loaded figure-it-out through the Skill tool on a name-only listing. The docs question stays open. The docs do not say whether a `skillOverrides` value of `"name-only"` overrides frontmatter `disable-model-invocation: true`. If frontmatter wins, the Skill tool keeps refusing gated siblings (#43809), and Claude Code needs the path route too. One `/skills` check or one `Skill` call settles it.
2. Hit rate. The [2026-10-10 results record](../evals/promises/results/2026-10-10-use-the-skill.md) compares the shipped deslop wording with its old-text control. It does not isolate the step 5 wording from the Report wording or compare "Use the X skill", "Call the Skill tool with X", `/X`, and a path as separate arms. The 2026-11-01 eval in [Evidence on reliability](#evidence-on-reliability) runs those four forms and "Load the X skill" as separate arms at one task-triggers line. The gain at other load sites is unmeasured.
3. Grok Build and Hermes. [Codex and Grok Build](#codex-and-grok-build) covers what Grok Build's docs and the 2026-11-01 eval show. Hermes docs and source were not inspected for how it handles sibling skills.
4. Cursor. Its skills docs URL returned 404, and nothing else was inspected.
