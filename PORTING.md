# Porting notes

This is a port of [cursor/plugins/pstack](https://github.com/cursor/plugins/tree/main/pstack) (MIT, by [poteto](https://x.com/poteto)) from Cursor to a CLI-agnostic skill set that installs with [`npx skills`](https://skills.sh) and runs in Claude Code, Codex, and Hermes.

Upstream is the source of truth for the workflows themselves. This file records every systematic substitution so future syncs from upstream can reapply them.

## Port additions beyond substitution

- **documentation-impact** (`skills/documentation-impact/`) is a port addition for authoring and independently reviewing documentation affected by a change. Preserve its auto-invocable metadata, `tools/skill-trigger-cases.json` entry, README and guide entries, central Poteto completion trigger, and Babysit and Shipping readiness hooks during sync. Preserve its canonical author result rules. The pass covers local work without a PR and binds any required independent review verdict to the examined artifact and documentation context. Visual tools remain optional. Keep model selection and lifecycle orchestration in the calling workflow.
- Upstream's `tdd` and `teach` skills are renamed `poteto-tdd` and `poteto-teach` so a global install cannot clobber identically named skills a user already has; the bug-fix playbook, README, and guide reference the new names.
- The **pstack-harness** skill (see the substitution map) is new in this port. Its primitives include a **worklist adapter**. "Open a worklist" defines ordered items and their states, not a tool name. The agent inspects live capability descriptions, makes at most one semantic discovery query when the harness defers capabilities, and prefers native structured work tracking when it is available. If discovery finds none or any call is rejected, the agent stops trying that carrier for the rest of the task and maintains the same worklist through the harness's normal progress-update channel. Both are native carriers. Do not preserve product-specific task-tool names, exact-name lookup instructions, scratch task files, retries, or fallback narration during sync. A durable file is only for workflows that must resume across sessions. A companion universal rule, **named sibling skills are files**: most pstack skills are gated against model invocation and absent from the tool inventory, so cross-references like "the architect skill" or a principle leaf are satisfied by reading the sibling directory's SKILL.md from the installed skills root, never by reporting the skill missing or editing its gating; poteto-mode's Principles intro anchors the same rule inline.
- `setup-pstack` checks the structured task tools (port addition, 2026-09). Claude Code 2.1.284 ships `TaskCreate`, `TaskUpdate`, `TaskList`, and `TaskGet` only on Claude 3.x, Opus 4 to 4.7, Sonnet 4 to 4.6, and Haiku 4.5. `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` in the environment or in a settings file's `env` block provides them on every model. Codex 0.158.0-alpha.2.1 keeps `update_plan` off until `config.toml` holds `[tools.update_plan]` followed by `enabled = true`. The published config reference at developers.openai.com and the repository's `docs/config.md` stub omit that key. The shipped `codex-rs/core/config.schema.json` defines it with `enabled` defaulting to false, and Codex rejects a bare boolean. On 2026-09-29, with the Claude switch on and tool search on, the default, the task tools arrived deferred, Sonnet kept no worklist in 4 of 4 `/poteto-mode` runs, and Opus searched for them and made one umbrella task. With `ENABLE_TOOL_SEARCH=false`, Sonnet made one task per playbook step in 2 of 2 runs, and a trivial first turn rose from 25,770 to 45,907 input tokens. With the Codex switch on, two `$poteto-mode` runs called `update_plan` with the playbook steps verbatim. With that switch off, Codex posted the steps as a numbered list with states, the pstack-harness fallback. Hermes has no known switch. The setup step reads the files and recommends the exact lines and the scope. It writes only after an explicit yes and merges without dropping keys, because the files are the user's own harness configuration and the tool-search cost is the user's to weigh. The port adopts no `todo.md` fallback, so the worklist adapter's rule against scratch task files stands. The other port, [michael-denyer/pstack-claude](https://github.com/michael-denyer/pstack-claude), names the Claude switch in its poteto-mode and falls back to an uncommitted `todo.md`. On sync, keep the setup step, the two hints-table cells in the **pstack-harness** skill, and the guide sentence.
- The **pstack-harness** skill owns the three-root runtime contract. `PSTACK_SKILLS_ROOT` comes from the logical path of the loaded harness skill and works without Git or network access. `PSTACK_SOURCE_ROOT` accepts only the configured HTTPS or SSH identity for `mdsmithaustin/pstack`. Physical symlink ancestry is only a source candidate. A copied install creates a private shallow clone when a fresh trunk read needs one, and the program removes only a generated directory with its ownership marker. `PROJECT_ROOT` stays separate for consumer control skills. A source resolution, identity, clone, fetch, or object failure stops the trunk read. Installed files are never its fallback. `tools/check-skill-content.py` rejects both runtime substitutions from upstream in every raw skill Markdown line, including fenced templates. Keep this contract and lint during future syncs.
- Codex does not honor `disable-model-invocation`, so every skill that sets it also carries `agents/openai.yaml` with `policy.allow_implicit_invocation: false` — the Codex-standard analog. The two flags must stay in sync: adding or removing one means adding or removing the other.
- Deliberate divergence from upstream #300: **how**, **why**, and **unslop** stay auto-invocable in this port (no `disable-model-invocation`, no `agents/openai.yaml`), because they own high-value automatic triggers in the maintainer's roster ("how does X work", motivation questions, prose cleanup). Do not reapply upstream's gating to these three on future syncs; `typescript-best-practices` and `make-bot-ui` keep it.
- Four sites carry a conditional GitNexus nudge, active only when `.gitnexus/` exists in the repo: the **how** skill (SKILL.md and `references/explorer-prompt.md`) seeds exploration with `gitnexus query`/`context`/`trace`; **blast-radius** seeds the change map with `gitnexus detect-changes`/`impact`; the **refactoring** playbook enumerates callers with `gitnexus impact`/`context` before a migration wave; and the Code review playbook's review lens lists a shared symbol's callers with `gitnexus impact`. Freshness-first policy: an existing index is refreshed with `gitnexus analyze --index-only` (incremental, no-op when up to date) before the graph is consulted — by the lead only, never from parallel arms (concurrent analyzes can corrupt the KuzuDB store). Creating a first index stays suggest-only. The code itself remains the source of truth: the index reflects the last analyzed commit and never sees uncommitted edits. No-op on hosts and repos without GitNexus.
- The GitHub watcher treats a PR whose head has no checks as having no CI (port addition, 2026-09). An empty GraphQL rollup proves it, so the watcher reads `ci-clean` instead of throwing `ChecksUnavailable`. It still throws that retryable error when an earlier commit on the PR had checks, because the head's checks may not be registered yet. So a later push that never gets checks in a repo with CI, such as a path-filtered or `[skip ci]` commit, still ends at the error cap. Upstream throws whenever both check sources are empty. Keep this on sync.
- The GitHub watcher keeps a GitHub Enterprise host (port addition, 2026-10). It reads the host from the origin remote or the PR URL, passes it to every `gh` call as `--repo <host>/<owner>/<repo>` and to GraphQL as `--hostname <host>`, and renders status links on it. An explicit `--owner`, `--repo`, and `--pr` outside a checkout uses `GH_HOST`, else github.com. Upstream assumes github.com. Keep the host through the watcher's context types on sync, and keep the Babysit playbook's `GH_HOST` sentence.
- The GitHub watcher (`skills/poteto-mode/scripts/watch-pr`) treats every review bot alike, not only Cursor Bugbot: a thread carries `bot: { login, passes } | null`, and `READY` waits while a bot is still a requested reviewer (`WAITING` with `pending-review-bots`), which is how GitHub Copilot code review shows up before it posts. Repos without review bots see no change. Upstream still has `isBugbot`/`bugbotReviewPasses`; on sync, keep the port's shape and re-apply the babysit playbook and triage-reference wording.
- Two roles beyond upstream's roster: `trail reviewer` (the show-me-your-work reviewer; upstream says "a different model family", which has no answer inside one vendor) and `default` (the entry for a spawn whose skill names no role, shipped as `inherit-parent`). The harness skill's "No improvised models" rule sends every role-less spawn through `default`; on sync, keep both roles and the show-me-your-work wording that resolves through `trail reviewer` and steps down a tier when it matches the working model.
- **Opening a PR** says how to post PR evidence (port addition, 2026-09). Follow any attachment rule the repo's `AGENTS.md` or PR template sets, upload with `gh … --attach` (gh 2.99.0 or later), never through undocumented endpoints, and confirm each posted URL returns `200` with `gh auth token`. Report an upload blocker only when no gh at 2.99.0 or later is available or a retry fails. Upstream says only to attach videos or screenshots. Keep both the repo-rule clause and the **Attachments** paragraph on sync.
- The models config carries reasoning effort and per-harness sections (port addition, 2026-09): an entry is `model` or `model@effort`; `## codex`, `## claude-code`, and `## hermes` sections override the flat lines for that harness; precedence, the effort policy (floor `high` on Codex and Hermes, `xhigh` there for the hardest roles, `inherit-parent` where subagents inherit the session effort, `max`/`ultra` only when written), and the Codex alias translation (`fable` → `gpt-5.6-sol@max`, `opus` → `gpt-5.6-sol@xhigh`, `sonnet` → `gpt-5.6-terra@high`, `haiku` → `gpt-5.6-luna@high`) live in one place, the **pstack-harness** skill, and every reader points there instead of restating the layering. `skills/setup-pstack/scripts/check-models-config.py` lints the file (unknown roles, bad efforts, per-model effort support, duplicate roles and sections, and `none` or `ultra` under `## claude-code`); `skills/setup-pstack/examples/pstack-models.md` is the shipped default and CI lints it. On sync, re-apply the one-phrase "with its configured effort per the **pstack-harness** skill" hook to any new reader upstream adds. Upstream's setup-pstack budget ask (upstream #366: `unlimited`, `large`, `medium`, `small`) ports onto this grammar: the budget rewrites the `@effort` suffix of every real entry, harness sections and suffixed aliases included, instead of the effort token inside a Cursor slug; `unlimited` pins `max`, which is upstream's `keep max` since upstream defaults sit at `max`; the port adds a fifth option, `default — keep as written`, that applies no budget, because it is the only option that keeps every per-role effort as written, and on Claude Code, where the effort policy leaves an unwritten effort at the session effort, it changes nothing; and the `# budget: <label> (<effort>)` comment is recorded in the file and read back by setup-pstack, never at runtime.
- A rejected model is handled in one place, the **pstack-harness** skill: omit it, inherit the session model, and report the substitution. Upstream #422 gave `how`, `why`, `reflect`, `swarm`, `arena`, and `interrogate` their own fallbacks to a role's default, which the port does not carry. On sync, keep each skill's rejection sentence pointing at pstack-harness.
- The models config is layered workspace-first: a role line in `.agents/pstack-models.md` overrides `~/.agents/pstack-models.md`; setup-pstack preserves values it cannot validate (another harness's choices) and has a write-fallback ladder (shell tool → workspace file → print) for harnesses that cannot write to the home directory.

- The **Code review** playbook (`skills/poteto-mode/playbooks/code-review.md`) and its review lens (`skills/poteto-mode/references/review-lens.md`) are new in this port with no upstream counterpart. Upstream routes a review request to Investigation, where no step loads the design principles. Keep the Code review selector entry and the Investigation entry's pointer to it. The lens holds review questions and a smells table. The rule text stays in the principle leaves, scoped to review.

They carry the two pieces of judgment content retained when GSD was retired from the maintainer's stack: the failing-direction rule with the verify-command traps, and the edge and prohibition probes run at spec time. Preserve the skill contract's evidence provenance, promotion gate, diagnostic and no-file-change boundaries, and write-authority checks. Discovery is auto-invocable, matching **verify-commands** and **spec-probes**; keep all three `(port addition)` README rows. Six references, same target, and the only reason is that `tools/check-skill-content.py` resolves a relative path and cannot see a prose one. - `.claude/settings.json` is fork-only and sets `attribution.sessionUrl` to `false`. Claude Code otherwise appends a `Claude-Session:` trailer carrying a private session URL to commits and pull request bodies made from a cloud or Remote Control session, on by default. That scoping is why only four sessions left traces rather than all of them. Nothing in this repository's skills or tooling caused it and nothing there could suppress it, because the control is a harness setting, which is what this file supplies. It reached 41 commits here across four sessions before anyone noticed and this repository is public, so the history was rewritten and the trailers removed. The file drops only the URL and leaves `Co-Authored-By` intact. Shared project settings outrank user settings in Claude Code's precedence order, so this beats whatever a contributor has in their own `~/.claude/settings.json`; only their `.claude/settings.local.json` or an organization's managed settings outrank it. Being Claude Code specific is not new ground for the port, which already ships `agents/openai.yaml` for Codex and a `.github/` directory. On sync, keep the file.

## Canon rules

Rules drawn from the software-design canon (Evans, Fowler, Beck, Martin, and the BDD authors) enter only after a paired screen measures a change in agent behavior. A later rewording that keeps a rule's screened meaning may land without a new screen when this section discloses it. A paired screen runs poteto-mode through `/poteto-mode` or `$poteto-mode` on the same task twice, once with the current skill text and once with the rule added, on Claude Sonnet 5 and on Codex with gpt-6-sol. A repository screen runs in an isolated `sbx` sandbox on a pinned upstream repository. A fixture screen gives the agent a small project of a few files in the prompt. Preserve each owner during sync. Do not reintroduce a rule listed below as not adopted without a new screen.

| Rule | Owner | Source | Screen result |
|---|---|---|---|
| Use the domain's words. Read the nearest glossary if one exists, such as a `CONTEXT.md`, use its terms, and never use a word it marks as one to avoid. `CONTEXT.md` and its `_Avoid_` list come from the optional `domain-modeling` companion, and pstack does not create either. | `principle-model-the-domain` | Evans, [Domain-Driven Design Reference](https://www.domainlanguage.com/ddd/reference/), Ubiquitous Language and Intention-Revealing Interfaces | Repository screen on NousResearch/hermes-agent: 6 of 6 runs passed with the rule and 1 of 6 without, across both agents. |
| Write Given, When, Then tests in the project's existing framework. Do not add Cucumber, a Gherkin runner, or `.feature` files unless the project already runs one or the user explicitly asks for Cucumber, a runner, or `.feature` files. A request for Gherkin-style tests is not such a request. | `principle-test-behavior-not-implementation` | [Cucumber Gherkin reference](https://cucumber.io/docs/gherkin/reference/), [Dan North, Introducing BDD](https://dannorth.net/blog/introducing-bdd/) | Fixture screen: in 4 of 4 pairs where the agent read the rule, 2 per agent, the run without it added a Gherkin runner and `.feature` files and the run with it did not. | In review, flag one word's different concepts combined into one type. | `principle-model-the-domain` | Evans, Bounded Context; [Fowler, BoundedContext](https://martinfowler.com/bliki/BoundedContext.html) | Admitted for review. Review screen. The Code review playbook, its review lens, and the five review rows above entered together. A repository screen seeded six flawed pull requests and two clean controls on the pinned omnigent and hermes-agent commits. A judge from the other model family, calibrated on labeled sample reviews for every case, graded each review. With the playbook, Claude Sonnet 5 fully found the flaw in 9 of 12 reviews and at least partly found it in 12 of 12, against 6 of 12 and 9 of 12 without it. Codex with gpt-6-sol read the playbook and the leaves in every run and found 1 of 12, at least partly 2 of 12, against 0 of 12 and 1 of 12 without it. Admission rests on the Claude result. The text as shipped, reworded after review to apply only in review, was screened again on the same cases. Claude fully found the flaw in 8 of 12 reviews and at least partly in 12 of 12. Codex found 1 of 12 and at least partly 2 of 12. Neither agent raised a false alarm on the controls. The review rules are scoped to review in their leaves, so their effect on building stays unmeasured. ## Named-agent portability

Root `agents/*.md` owns upstream persona text and metadata. `tools/generate-subagents.py` owns the explicit port mapping and generates `skills/pstack-harness/references/subagents/roles.json`. The installed `pstack-harness/scripts/subagents.py` reads this bundle without Git, network access, or a source checkout. Do not hand-edit generated payloads.

Native Claude wrappers use normalized names and translate upstream `is_background` to `background`. Codex wrappers use TOML with `name`, `description`, and `developer_instructions`. Both contain complete persona briefings and installed skill paths. They leave model, effort, tool, and sandbox policy unset. Comment Sicko may edit comments; preserve its ban on application-code edits. Hermes has no confirmed arbitrary custom-agent-file loader, so its delegate receives the complete briefing through context.

The named-role contract preserves the aliases `poteto-agent` and `Comment Sicko`. A native registration requires generated bytes that match the briefing rendered from the current skills root, or from an alias root whose named `SKILL.md` files resolve to the same files. It also requires live catalog confirmation. Otherwise generic native delegation, own-CLI subprocesses, and sequential arms receive the same full persona. Keep the configured arm count and existing model policy. Native installation is optional, uses an explicit project or user destination, and refuses user-managed or edited role files. Payload checks never claim actual native activation.

Effort agents are a port addition (2026-09). Claude Code's spawn tool has no per-call effort, and a custom agent's `effort` frontmatter overrides the session effort and combines with a per-call `model`, measured on Claude Code 2.1.284. A delegate's nested spawns inherit the delegate's effort. So `subagents.py install --harness claude-code` also writes `pstack-effort-<level>.md` for `low`, `medium`, `high`, `xhigh`, and `max`. Their body is `skills/pstack-harness/references/subagents/effort-delegate.md`, which is port-owned and not generated from upstream. The pstack-harness skill's "Set an arm's effort" owns the dispatch rule, and its effort policy scopes the `high` floor to harnesses whose subagents get a model-default effort. On sync, keep that section and that scoping sentence, keep synced skills' `subagent_type: general-purpose` lines as they arrive, and never restate the rule in a synced skill. CI does not prove the mechanism, because that needs an authenticated `claude`. After a Claude Code upgrade, run `python3 tools/probe-effort-dispatch.py`, which spawns three wrappers above and below the session effort, one of them carrying a persona briefing, and a `general-purpose` control. It fails on an `agent_type`, `effort`, or `perTurnEffort` mismatch, on a requested arm with no spawn, on a case with no spawns, or on a `claude` invocation that exits nonzero or times out. Failure signal: nonzero exit. The script prints its JSON report to stdout and writes the same content to `report.json` in a fresh `pstack-effort-dispatch-probe-` temp directory, named in the report as `run_root`.

After every upstream agent change, run `python3 tools/generate-subagents.py`. Failure signal: nonzero exit for unsupported source input. Then run `python3 tools/generate-subagents.py --check`. Failure signal: nonzero exit for source-to-bundle drift. Commit the upstream source and generated payload together. Reapply the named-role callsite and setup instructions during sync.

Run `python3 -m unittest discover -s tools -p 'test_subagents.py'` with Python 3.12. Failure signal: nonzero exit or zero collected tests. Run `python3 tools/probe-subagent-install.py` for actual pinned project installations with symlinks and copies. Failure signal: nonzero exit; the JSON report identifies the failed case. The probe uses temporary roots and never registers roles into the user's real configuration. Native loader and child-behavior checks require separate live-session evidence.

## Single-model upstream cuts

Upstream removes instructions it judges a single lead model no longer needs. The port runs on Codex too, so a cut whose evidence covers only that model waits until the port checks it on a GPT lead. The port takes a cut without that check only when the rule survives in the same file or in poteto-mode, or when upstream's A/B already covered a GPT model.

Upstream #414 (70b2dc8, 15 cuts) and #419 (b0b9c7a) justified their lead-side cuts with Opus 5.5 runs only. The port checked them on 2026-09-27 and took all of them:

- 14 of #414's cuts, plus #419's poteto-tdd, never-block, and outcome-oriented cuts, keep their rule in the same file or in poteto-mode, so the text settles them.
- The rest ran through the held-cuts screen in `evals/canon` on gpt-5.6-sol and Sonnet leads, 3 paired runs per arm, graded by hidden tests and the chain census:
  - The review lines in `feature`, `bug-fix`, and `refactoring`: the lead inspected the delegate's work (a read of an edited file, or git diff, show, or status) in every run where a delegate wrote code, with the lines and without them.
  - The nested-spawn reminder: Codex delegated in every run either way, and Sonnet delegated more often without it.
  - The `how` + `why` fan-out line: Codex fanned out in every run either way, and Sonnet never did either way.
  - #414's poteto-tdd "Run nearby validation" step: no restored run read poteto-tdd, and a test run wider than one test followed the last edit in 47 of 48 runs.
  - Hidden tests passed in 16 of 24 runs without the cuts and 19 of 24 with them.

## What deliberately did not change

- Skill bodies, playbooks, and principles retain upstream engineering content except for the substitutions and port additions recorded above.
- Frontmatter extras (`mode`, `icon`, `color`, `reminder`, `disable-model-invocation`): Cursor-flavored but harmless; CLIs that don't know a key ignore it.
- `agents/` remains unchanged upstream text. The port generates an installed bundle and native wrappers from it, as described above.

## Syncing from upstream

The upstream sync workflow is available through the manual-dispatch GitHub Action in `.github/workflows/upstream-sync.yml`. Local schedules, machine paths, logs, and maintainer-specific tooling are intentionally not documented in this repository.

Manually:

1. `git remote add upstream https://github.com/cursor/plugins.git` (sparse-checkout `pstack`).
2. Diff upstream's `pstack/` against the SHA in `.github/upstream-sha` (originally the import commit).
3. Reapply the substitution map to the incoming hunks, keep the port additions intact, regenerate and check the role bundle, and bump `.github/upstream-sha`.
4. Hold any cut that upstream justifies by one model's behavior until it meets the bar in **Single-model upstream cuts**.
