# Porting notes

This is a port of [cursor/plugins/pstack](https://github.com/cursor/plugins/tree/main/pstack) (MIT, by [poteto](https://x.com/poteto)) from Cursor to a CLI-agnostic skill set that installs with [`npx skills`](https://skills.sh) and runs in Claude Code, Codex, Hermes, and Grok Build.

Upstream is the source of truth for the workflows themselves. This file records every systematic substitution so future syncs from upstream can reapply them.

## Substitution map

| Upstream (Cursor) | This port |
|---|---|
| `~/.cursor/rules/pstack-models.mdc` (always-applied rule) | `~/.agents/pstack-models.md` (plain file; agents read it through `check-models-config.py --resolve`) |
| Model slugs `claude-fable-5-thinking-max`, `gpt-5.6-sol-max`, `grok-4.6-fast-xhigh`, `claude-opus-5-thinking-xhigh` | `fable`, `opus`, `sonnet`, `haiku` (Claude Code subagent model aliases). Since upstream 0.15.3 the defaults are `claude-opus-5-5-max` (judgment), `gpt-5.6-sol-max`, and `grok-4.7-xhigh-fast` (code), which map by role to `opus`, `fable`, and `sonnet`. Judgment and prose use `opus` because upstream evaluated its 0.15.3 prose cuts on Opus 5.5. `fable` keeps a panel slot, so panels are `fable`, `opus`, `sonnet`. The three-entry panels drop `haiku`, which stays a valid alias. The `## codex` section pins judgment roles to `gpt-6-sol@max` and `trail reviewer` to `gpt-6-astra@high`, one tier above the sol lead and above `swarm workers` on luna, so verdicts and audit lanes stay cross-model. On Codex the aliases translate to gpt-6 models, each run on the newest gpt-6 release Codex lists, per setup-pstack's models config reference. In a CLI with no translation (Hermes), treat an alias as `inherit-parent`: the subagent runs on the session model and multi-model panels become same-model panels with differentiated briefs. |
| Project skills at `.cursor/skills/`, user skills at `~/.cursor/skills/` | `.agents/skills/` and `~/.agents/skills/`. Codex uses the shared directory. Claude Code also uses its installer-created `.claude/skills/` links. Hermes project skills require trust; global shared skills need `skills.external_dirs` or a native Hermes installation. The installer supports the `hermes-agent` target and may skip its project link when `.hermes` is absent. |
| Plugin-installed skill paths under `~/.cursor/plugins/` | installed skill paths under `~/.agents/skills/`, `~/.claude/skills/`, `~/.codex/skills/` |

Fresh pstack trunk reads use a verified `PSTACK_SOURCE_ROOT` and fetch `+refs/heads/main:refs/remotes/origin/main` before `git show origin/main:skills/...`. Consumer control skill reads use `PROJECT_ROOT`. All three are absolute and quoted. |
| Workspace transcripts: `agent-transcripts/` dir named by the system prompt; `~/.cursor/projects/<slug>/agent-transcripts/` | Per-CLI session stores. Claude Code: `~/.claude/projects/<slug>/*.jsonl` where `<slug>` is the resolved workspace path with every character other than a letter or digit turned into `-` (so `/Users/you/proj` becomes `-Users-you-proj`). Codex: `~/.codex/sessions/<year>/<month>/<day>/rollout-*.jsonl`. Hermes: its session-log directory (check its data dir). The privacy rule carries over: stay inside the current workspace's sessions; never glob across other projects. |
| Cursor cloud agents (`environment: "cloud"`, `cloud_base_branch`), Cursor dashboard | Background subagents in isolated git worktrees. The port removes the cloud spawn parameters, because every supported CLI runs its workers locally. Probe liveness via the ledger, `gh`, and pushed branches. |
| `cursor-team-kit` `/deslop` | the port-owned **deslop** skill (`skills/deslop/`), auto-invocable, with `skills/deslop/CREDITS.md` carrying the MIT notices for the Cursor, Addy Osmani, and Matt Pocock rules it drew on. Upstream callers say "`/deslop` from `cursor-team-kit`"; the port drops the plugin clause and keeps `/deslop` |
| `cursor-team-kit` `control-ui` / `control-cli` | the project's verification skill (`verify-<app>`, generated by `/create-verification-skill`) |
| Cursor built-in `create-skill` | the authoring guidance in `skills/poteto-mode/playbooks/authoring-a-skill.md` (SKILL.md per the [agentskills.io](https://agentskills.io) format) |
| Cursor built-in `babysit` skill | any similarly-named built-in; the Babysit playbook still owns these requests |
| Cursor `/loop` | Claude Code `/loop`; in a CLI without one, re-prompt on an interval or run a watcher subagent |
| Cursor automations / `api2.cursor.sh` webhooks (benny) | any scheduled agent runner (Claude Code scheduled agents, cron-driven CI job) exposing a webhook or schedule; paths move from `.cursor/automations/` to `.agents/automations/` |
| `.cursor-plugin/plugin.json` | removed; `npx skills` discovers `skills/*/SKILL.md` directly |
| Origin forge CLI (`origin pr ...`, upstream's optional alternative to `gh` for PR create/view/merge) | kept verbatim. Every use is gated on `command -v origin` succeeding, with `gh` as the stated default, so the text is a no-op on hosts without Origin. Graphite (`gt`) remains optional only for Orchestrate frontier discovery. `orch frontier set` uses `gh` for a same-repository linear stack and runs `gt` only with `--graphite`. Never restore a hard Graphite requirement during sync. |
| Cursor `Task` semantics (`subagent_type`, `model`, `readonly`, `environment: "cloud"`) assumed everywhere | a new **pstack-harness** skill (`skills/pstack-harness/`) maps spawning, per-subagent models, parallelism, read-only posture, structured questions, loops, and transcript access to Claude Code (`Task` tool), Codex (`spawn_agent`, with `codex exec` subprocesses as the fallback), Hermes (delegation toolset, `hermes -z` subprocesses, `hermes sessions export`), and Grok Build (`spawn_subagent`, `grok -p` subprocesses, per-session directories); fan-out skills point to it |

## Port additions beyond substitution

- `worktree-audit.sh` uses inline Python standard-library code for transcript mtimes, local dates, and integer-day recency on Linux and macOS. Preserve it during sync instead of restoring BSD `stat` and `date` calls. The script requires `python3`, `rg`, and `jq`.

- **documentation-impact** (`skills/documentation-impact/`) is a port addition for authoring and independently reviewing documentation affected by a change. Preserve its auto-invocable metadata, `tools/skill-trigger-cases.json` entry, README and guide entries, central Poteto completion trigger, and Babysit and Shipping readiness hooks during sync. Preserve its canonical author result rules. The pass covers local work without a PR and binds any required independent review verdict to the examined artifact and documentation context. Visual tools remain optional. Keep model selection and lifecycle orchestration in the calling workflow.
- **deslop** (`skills/deslop/`) is a port addition that replaces cursor-team-kit's `/deslop` with a pstack-owned code cleanup pass: nineteen numbered rules over the branch's changed hunks, a test run that proves behavior unchanged, and a report. `skills/deslop/CREDITS.md` ships inside the skill directory so the MIT notices travel with every `npx skills` copy. On sync, keep the skill, its trigger row in `tools/skill-trigger-cases.json`, the README and guide entries, poteto-mode's Before commit trigger, the `/deslop` lines in Opening a PR, both autopilot playbooks, and the multi-phase checklist, and the ledger promises `deslop-available-for-code`, `opening-a-pr-deslops-diff`, and `deslop-cleans-code-slop`. Upstream never writes `skills/deslop/`; if it ever does, keep whichever version has the rule table.
- Upstream's `tdd` and `teach` skills are renamed `poteto-tdd` and `poteto-teach` so a global install cannot clobber identically named skills a user already has; the bug-fix playbook, README, and guide reference the new names.
- The **pstack-harness** skill (see the substitution map) is new in this port. Its primitives include a **worklist adapter**. "Open a worklist" defines ordered items and their states, not a tool name. The agent inspects live capability descriptions, makes at most one semantic discovery query when the harness defers capabilities, and prefers native structured work tracking when it is available. If discovery finds none or any call is rejected, the agent stops trying that carrier for the rest of the task and maintains the same worklist through the harness's normal progress-update channel. Both are native carriers. Do not preserve product-specific task-tool names, exact-name lookup instructions, scratch task files, retries, or fallback narration during sync. A durable file is only for workflows that must resume across sessions. A companion universal rule, **named sibling skills are files**: most pstack skills are gated against model invocation and absent from the tool inventory, so cross-references like "the architect skill" or a principle leaf are satisfied by reading the sibling directory's SKILL.md from the installed skills root, never by reporting the skill missing or editing its gating; poteto-mode's Principles intro anchors the same rule inline.
- `setup-pstack` checks the structured task tools (port addition, 2026-09). Claude Code 2.1.284 ships `TaskCreate`, `TaskUpdate`, `TaskList`, and `TaskGet` only on Claude 3.x, Opus 4 to 4.7, Sonnet 4 to 4.6, and Haiku 4.5. `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` in the environment or in a settings file's `env` block provides them on every model. Codex 0.158.0-alpha.2.1 keeps `update_plan` off until `config.toml` holds `[tools.update_plan]` followed by `enabled = true`. The published config reference at developers.openai.com and the repository's `docs/config.md` stub omit that key. The shipped `codex-rs/core/config.schema.json` defines it with `enabled` defaulting to false, and Codex rejects a bare boolean. On 2026-09-29, with the Claude switch on and tool search on, the default, the task tools arrived deferred, Sonnet kept no worklist in 4 of 4 `/poteto-mode` runs, and Opus searched for them and made one umbrella task. With `ENABLE_TOOL_SEARCH=false`, Sonnet made one task per playbook step in 2 of 2 runs, and a trivial first turn rose from 25,770 to 45,907 input tokens. With the Codex switch on, two `$poteto-mode` runs called `update_plan` with the playbook steps verbatim. With that switch off, Codex posted the steps as a numbered list with states, the pstack-harness fallback. Hermes has no known switch. The setup step reads the files and recommends the exact lines and the scope. It writes only after an explicit yes and merges without dropping keys, because the files are the user's own harness configuration and the tool-search cost is the user's to weigh. The port adopts no `todo.md` fallback, so the worklist adapter's rule against scratch task files stands. The other port, [michael-denyer/pstack-claude](https://github.com/michael-denyer/pstack-claude), names the Claude switch in its poteto-mode and falls back to an uncommitted `todo.md`. On sync, keep the setup step, the two hints-table cells in the **pstack-harness** skill, and the guide sentence.
- `setup-pstack` checks whether Codex's native subagent spawning is available (port addition, 2026-10). pstack's native Codex delegation needs `spawn_agent`. Without it, the **pstack-harness** skill falls back to `codex exec` subprocesses or inline arms. On Codex 0.160.0, whether a session has `spawn_agent` depends on these:
  - the `multi_agent` and `multi_agent_v2` features
  - `[agents]` `enabled = false`, which removes it while the `multi_agent` row reads true
  - the selected model's `multi_agent_version`
  - launch flags, spawn depth, and tool search

  So step 0c treats a live session as the answer and config as signals. It offers an edit only when a session confirms `spawn_agent` is missing, and only for a possible cause a config file shows. On sync, keep step 0c of setup-pstack and the setup guide's sentences.
- The **pstack-harness** skill owns the three-root runtime contract. `PSTACK_SKILLS_ROOT` comes from the logical path of the loaded harness skill and works without Git or network access. `PSTACK_SOURCE_ROOT` accepts only the configured HTTPS or SSH identity for `mdsmithaustin/pstack`. Physical symlink ancestry is only a source candidate. A copied install creates a private shallow clone when a fresh trunk read needs one, and the program removes only a generated directory with its ownership marker. `PROJECT_ROOT` stays separate for consumer control skills. A source resolution, identity, clone, fetch, or object failure stops the trunk read. Installed files are never its fallback. `tools/check-skill-content.py` rejects both runtime substitutions from upstream in every raw skill Markdown line, including fenced templates. Keep this contract and lint during future syncs.
- Codex does not honor `disable-model-invocation`, so every skill that sets it also carries `agents/openai.yaml` with `policy.allow_implicit_invocation: false` — the Codex-standard analog. The two flags must stay in sync: adding or removing one means adding or removing the other.
- Deliberate divergence from upstream #300: **how**, **why**, and **unslop** stay auto-invocable in this port (no `disable-model-invocation`, no `agents/openai.yaml`), because they own high-value automatic triggers in the maintainer's roster ("how does X work", motivation questions, prose cleanup). The port-owned **deslop** skill is auto-invocable for the same reason: the guide tells readers to say `deslop it`, and a gated skill never fires on that phrase. Do not reapply upstream's gating to these four on future syncs; `typescript-best-practices` and `make-bot-ui` keep it.
- Four sites carry a conditional GitNexus nudge, active only when `.gitnexus/` exists in the repo: the **how** skill (SKILL.md and `references/explorer-prompt.md`) seeds exploration with `gitnexus query`/`context`/`trace`; **blast-radius** seeds the change map with `gitnexus detect-changes`/`impact`; the **refactoring** playbook enumerates callers with `gitnexus impact`/`context` before a migration wave; and the Code review playbook's review lens lists a shared symbol's callers with `gitnexus impact`. Freshness-first policy: an existing index is refreshed with `gitnexus analyze --index-only` (incremental, no-op when up to date) before the graph is consulted — by the lead only, never from parallel arms (concurrent analyzes can corrupt the KuzuDB store). Creating a first index stays suggest-only. The code itself remains the source of truth: the index reflects the last analyzed commit and never sees uncommitted edits. No-op on hosts and repos without GitNexus.
- The GitHub watcher treats a PR whose head has no checks as having no CI (port addition, 2026-09). An empty GraphQL rollup proves it, so the watcher reads `ci-clean` instead of throwing `ChecksUnavailable`. It still throws that retryable error when an earlier commit on the PR had checks, because the head's checks may not be registered yet. So a later push that never gets checks in a repo with CI, such as a path-filtered or `[skip ci]` commit, still ends at the error cap. Upstream throws whenever both check sources are empty. Keep this on sync.
- The GitHub watcher keeps a GitHub Enterprise host (port addition, 2026-10). It reads the host from the origin remote or the PR URL, passes it to every `gh` call as `--repo <host>/<owner>/<repo>` and to GraphQL as `--hostname <host>`, and renders status links on it. An explicit `--owner`, `--repo`, and `--pr` outside a checkout uses `GH_HOST`, else github.com. Upstream assumes github.com. Keep the host through the watcher's context types on sync, and keep the Babysit playbook's `GH_HOST` sentence.
- The GitHub watcher (`skills/poteto-mode/scripts/watch-pr`) treats every review bot alike, not only Cursor Bugbot: a thread carries `bot: { login, passes } | null`, and `READY` waits while a bot is still a requested reviewer (`WAITING` with `pending-review-bots`), which is how GitHub Copilot code review shows up before it posts. Since 2026-10, `READY` also stops on a bot review of the head commit whose body reports a finding with no thread (the `review-findings` blocker, exit 8), until a PR comment from the PR author or a repository owner, member, or collaborator contains that review's full URL. A per-format parser registry reads Copilot's overview. An unreadable body from Copilot's login blocks, and another bot's unreadable body becomes a note on `READY`. Repos without review bots see no change. Upstream still has `isBugbot`/`bugbotReviewPasses`; on sync, keep the port's shape and re-apply the babysit playbook and triage-reference wording.
- Shipping lands GitHub PRs through `scripts/watch-pr/merge-gate` (port addition, 2026-10). The lead broke the prose landing gates three times in one week: once it merged before reading a bot's review body, once it missed red CI behind the watcher's first blocker, and once it reported CI it had not read. merge-gate reads the latest trusted verdict block (`Verdict:`, `Head:`, `Patch-id:`, `Docs:`) and recomputes the patch-id. It checks CI, bot review bodies, threads, and mergeability on the current head, reports every failed gate, and merges with `--match-head-commit`. It also refuses a base branch with a merge queue, because `gh pr merge` would only enqueue the PR, and the queue would land it later without rechecking the verdict, the bot reviews, or the open threads. `--override` posts its reason on the PR. On GitHub, Shipping never arms GitHub auto-merge, because it would merge later without these checks; the lead runs merge-gate when the watcher reports `READY`. Upstream lands with a bare `gh pr merge` or arms `--auto`, and has no verdict block.
- Two roles beyond upstream's roster: `trail reviewer` (the show-me-your-work reviewer and, since 2026-10, every independent verdict and review; upstream says "a different model family", which has no answer inside one vendor) and `default` (the entry for a spawn whose skill names no role, shipped as `inherit-parent`). Step 1 of the harness skill's Spawn a role sends every role-less spawn through `default`; on sync, keep both roles and the show-me-your-work wording that resolves through `trail reviewer`, and keep the resolver's `--work-model` step that moves it to another allowed model in the work model's family when it matches the working model, or marks it `same-model` when the config allows none in that family.
- **Authoring or modifying a skill** sends skill steps through the STE layer of **technical-writing** (port addition, 2026-10). Skill steps are procedures an agent executes. ASD-STE100 was written for procedures. Upstream's authoring guidance names no style standard. On sync, keep the sentence.
- **Opening a PR** says how to post PR evidence (port addition, 2026-09). Follow any attachment rule the repo's `AGENTS.md` or PR template sets, upload with `gh … --attach` (gh 2.99.0 or later), never through undocumented endpoints, and confirm each posted URL returns `200` with `gh auth token`. Report an upload blocker only when no gh at 2.99.0 or later is available or a retry fails. Upstream says only to attach videos or screenshots. Keep both the repo-rule clause and the **Attachments** paragraph on sync.
- The models config carries reasoning effort and per-harness sections (port addition, 2026-09): an entry is `model` or `model@effort`; `## codex`, `## claude-code`, `## grok`, and `## hermes` sections override the flat lines for that harness; the layering, the effort policy (floor `high` on Codex and Hermes, `xhigh` there for the hardest roles, `inherit-parent` where subagents inherit the session effort, `max`/`ultra` only when written), and the Codex alias translation (`fable` → `gpt-6-sol@max`, `opus` → `gpt-6-sol@xhigh`, `sonnet` → `gpt-6-sol@high`, `haiku` → `gpt-6-luna@high`, since 2026-10 each run on the newest gpt-6 release Codex lists; Grok Build, since 2026-10, maps every alias to `grok-4.7` and takes effort like Claude Code) are written once, in `skills/setup-pstack/references/models-config.md`, and applied by `check-models-config.py --resolve` (port addition, 2026-10). The **pstack-harness** skill points at the resolver, and every reader points at pstack-harness instead of restating the layering. Since 2026-10 a role's model and effort come from one line, a harness section beats a flat line in either file, and the Codex and Hermes floor applies only when the line names a model, because a full-history fork inherits the parent's effort. `skills/setup-pstack/scripts/check-models-config.py` lints the file (unknown roles, bad efforts, per-model effort support, duplicate roles and sections, `none` or `ultra` under `## claude-code`, and any effort but `low` through `xhigh` under `## grok`); `skills/setup-pstack/examples/pstack-models.md` is the shipped default and CI lints it. On sync, point any new reader upstream adds at **Spawn a role** in the **pstack-harness** skill instead of a per-skill copy of the layering, defaults, or fallbacks. Upstream's setup-pstack budget ask (upstream #366: `unlimited`, `large`, `medium`, `small`) ports onto this grammar: the budget rewrites the `@effort` suffix of every real entry, harness sections and suffixed aliases included, instead of the effort token inside a Cursor slug; `unlimited` pins `max`, which is upstream's `keep max` since upstream defaults sit at `max`; the port adds a fifth option, `default — keep as written`, that applies no budget, because it is the only option that keeps every per-role effort as written, and on Claude Code, where the effort policy leaves an unwritten effort at the session effort, it changes nothing; and the `# budget: <label> (<effort>)` comment is recorded in the file and read back by setup-pstack, never at runtime.
- Swarm picks each worker's role by what it does (port addition, 2026-10). A worker whose result comes from running something uses `swarm workers`. A worker that reads and judges code or a diff uses `trail reviewer`, and the caller finds the author's model before spawning it, to pass as `--work-model`. poteto-mode's subagent defaults name the exception. Upstream gives every worker one model. On sync, keep swarm step 4's split and Phase B's per-worker spawn call.
- Workers are local (port addition, 2026-10). Claude Code, Codex, Hermes, and Grok Build run every subagent on this machine, and every subagent ends with the session. Upstream's Cursor cloud workers outlive it. The port removes `environment: "cloud"`, `environment: "local"`, `cloud_base_branch`, cloud workers, and the cloud-sleeper wake chain from skills. A worker that must start from another pushed branch gets a worktree at that branch's SHA. `tools/skill-content-conventions.json` retires `environment: "cloud"`, `cloud_base_branch`, and `cloud-sleeper` under `skills/`. On sync, strip that wording from incoming hunks.
- Orchestrate runs local workers (port addition, 2026-10). Upstream's coordinator reattached cloud work after a restart and restacked in the cloud with Graphite. Here every worker ends with the session, so the playbook keeps its store at `.orchestrate/<project-slug>/` in the main checkout, keeps every brief in the store's `briefs/`, has workers push at their first commit, and after a restart reconciles each unfinished unit against the forge and its worktree before respawning a fresh worker there. One stacker per stack rebases with git and retargets with `gh` or Origin, one restack at a time, as in Autopilot-stack. Sub-coordinators spawn workers only where the CLI lets a subagent spawn. Because the stacker never writes Graphite metadata, `orch frontier set` discovers through `gh` by default and uses `gt` only with `--graphite`. Frontier discovery needs GitHub and `gh` even when Origin handles PR operations. On sync, keep these rules over upstream's cloud and `gt` stacker wording.
- Guard the Context Window has concrete triggers (port addition, 2026-10). Upstream's principle fires only when context is filling up, and other rules pull bulk into the lead: read every arena candidate end to end, return full subagent reports. The port adds thin returns (a subagent writes its report to a file or the PR and returns the verdict, blockers, and the pointer), a read budget of about 150 lines for the lead, and worklists copied from the prose before step 1 and the numbered steps instead of whole playbooks. Arena's lead reads every candidate's rationale and reads a full artifact only for the base or a criterion the cross-judge disputes. poteto-mode's principle entry and subagent defaults point at the rules. On sync, keep them.
- Playbook rules sit where the worklist extractor reaches them (port addition, 2026-10). The extractor prints the prose before step 1 as the first item, then the numbered steps, and stops at the first column-0 line after them. A Codex lead that copied only the steps lost Bug fix's "Delegate investigation" lead line. So each playbook keeps its rules before step 1 or inside a step, and only the **Reply:** line follows the steps. Orchestrate, multi-phase-plan, and Opening a PR say to read them in full and are exempt. `tools/test_playbook_shape.py` enforces the shape. Bug fix step 2 also spawns the `how` explainer and a **why** investigator before the lead reads source. On Codex 0.160.0 with gpt-6-sol at medium, upstream's wording got no how and why pair in 8 of 8 runs, and the lead wrote the fix itself in 3 of them. The spawn wording got the pair and a fix delegate in 7 of 7, and hidden tests did not move (2 of 5 against 2 of 4 on the subshell case). Claude leads spawn no investigators under either wording (PR 73).
- A failed mechanism never drops its directive (port addition, 2026-10). In the #116 repro, two Codex leads tried `git worktree add` for a delegate, hit a read-only `.git`, and did the work inline. An audit of 90 mechanism-and-directive sites found 25 with no failure instruction and 3 whose fallback dropped the intent. The top eight now say how to degrade and report. A failed resolver still spawns on inherited values, with `trail reviewer` on the session model and its verdict labeled as possibly same-model and each panel at its skill's default arm count, briefed as that skill says. An inline verdict is labeled `self-review`. A harness with no loop facility runs ticks by hand. Babysit reads the PR, bot review bodies, and unresolved threads through `gh` itself when the watcher cannot run, never reports the PR ready from them, stops when any of those queries fails, and treats a `status-query` blocker (exit 7) as unknown state. A Shipping verifier with no `verify-<app>` drives the surface by hand or returns at most `PASS+NOTES`. Pause-safely saves a binary patch and an untracked-files tarball when `git commit` fails. Autopilot-full still runs a tick when the trunk fetch fails and records the failed fetch. It skips only that tick's drift fix, because portable-paths forbids a stale trunk read.
- Forks have one sanctioned use (port addition, 2026-10). A fork, Claude Code's `fork` agent type or a Codex full-history fork, inherits the lead's context and runs on the lead's model and effort. Spawn a role allows it only for a role that resolves to `inherit-parent` for both, when the brief would otherwise restate what the lead already holds. It never forks a verdict, a review, or a role that resolves to a model or an effort. Upstream has no fork guidance. On sync, keep the rule.
- A Codex lead waits instead of racing its children (port addition, 2026-10). A census of real poteto-mode sessions since 2026-09-14 found that in 106 of 339 non-blocking Codex spawns (31%), the lead read overlapping files while its child worked. The median was about 127K characters of tool output per window. Claude Code leads raced in 8 of 306 spawns. Claude's lead resumes on a completion notice, while a Codex lead holds its turn. The Codex agent-cap paragraph now has each brief name its scope. The lead stays out of a running child's scope, except for a read a skill step assigns it alongside the child (arena's Phase D). It sends new facts to that child, and waits with `wait_agent` only once running children or queued arms own every remaining task. A fan-out still launches in full.
- Personas announce themselves (port addition, 2026-10). A persona brief, native or pasted, tells the child to put `persona: <id>` on its own line in its first reply, unless the persona fixes its own first output. Comment Sicko's fixed first line, `Yes... Ha ha ha... Yes!`, is its signature. Codex encrypts spawn messages, so a pasted briefing was otherwise unprovable from a transcript. Child replies are plaintext. Setup also recommends a project-scope Codex install for wrappers that run Codex with their own `CODEX_HOME`, which never read `~/.codex/agents/`. Upstream has neither. On sync, keep both.
- A rejected model is handled in one place, the **pstack-harness** skill: omit it, inherit the session model, and report the substitution. Upstream #422 gave `how`, `why`, `reflect`, `swarm`, `arena`, and `interrogate` their own fallbacks to a role's default, which the port does not carry. On sync, keep each skill's spawn sentence pointing at **Spawn a role**, which owns the rejection rule.
- The models config is layered: a workspace `.agents/pstack-models.md` sits over `~/.agents/pstack-models.md`, and a harness section beats a flat line in either file; setup-pstack preserves values it cannot validate (another harness's choices) and has a write-fallback ladder (shell tool → workspace file → print) for harnesses that cannot write to the home directory.

- The **Code review** playbook (`skills/poteto-mode/playbooks/code-review.md`) and its review lens (`skills/poteto-mode/references/review-lens.md`) are new in this port with no upstream counterpart.
