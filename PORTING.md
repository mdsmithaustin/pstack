# Porting notes

This is a port of [cursor/plugins/pstack](https://github.com/cursor/plugins/tree/main/pstack) (MIT, by [poteto](https://x.com/poteto)) from Cursor to a CLI-agnostic skill set that installs with [`npx skills`](https://skills.sh) and runs in Claude Code, Codex, Hermes, and Grok Build.

Upstream is the source of truth for the workflows themselves. This file records every systematic substitution so future syncs from upstream can reapply them.

- The **pstack-harness** skill (see the substitution map) is new in this port. Its primitives include a **worklist adapter**. "Open a worklist" defines ordered items and their states, not a tool name. The agent inspects live capability descriptions, makes at most one semantic discovery query when the harness defers capabilities, and prefers native structured work tracking when it is available. If discovery finds none or any call is rejected, the agent stops trying that carrier for the rest of the task and maintains the same worklist through the harness's normal progress-update channel. Both are native carriers. Do not preserve product-specific task-tool names, exact-name lookup instructions, scratch task files, retries, or fallback narration during sync. A durable file is only for workflows that must resume across sessions. A companion universal rule, **use named sibling skills yourself**: "Use the **architect** skill", or any other cross-reference by name, names a sibling directory under the installed skills root. On Claude Code the agent calls the Skill tool with the bare name, which loads a skill listed by name only. On Codex, Grok Build, Hermes, and other harnesses it reads `<installed skills root>/<name>/SKILL.md` in full. It never reports the skill missing, asks the user to type it, or edits how it loads. poteto-mode's Principles intro keeps the Claude Code half inline and points at this rule for the rest. Without that sentence, 1 of 3 Claude Code leads on 2026-10-10 loaded figure-it-out by file read, and with it 3 of 3 used the Skill tool. A second rule, **load only skills that someone named**, forbids loading a pstack skill found by listing or searching a skills directory unless the user or a loaded skill named it.

## Syncing from upstream

This section is the only sync procedure. A runner gives it three inputs: the recorded upstream commit, the latest upstream commit that touches `pstack/`, and a publish route. Without a runner, read the inputs yourself in step 1 and use the default route in step 10.

The manual-dispatch GitHub Action in `.github/workflows/upstream-sync.yml` is one runner. It needs the `CLAUDE_CODE_OAUTH_TOKEN` repository secret. Its checkout has `.no-mistakes.yaml` but no initialized gate, so it prepares the sync and reports publication as blocked. It does not push a branch or open a PR with its workflow token. A maintainer resumes the sync in an initialized checkout and publishes through the configured gate. The Action checkout is temporary; its local commits are not a durable handoff. Host-specific schedules, machine paths, and maintainer-specific tooling are intentionally not documented in this repository.

Run `tools/upstream-sync.sh` for the local scheduled runner. It requires Git, `gh`, Python 3, and authenticated Claude Code. It checks upstream and open sync PRs before invoking Claude. Each attempt starts with a fresh clone; attempts that invoke Claude get a unique branch and retain their clone. The runner pins the clone's initial commit before Claude runs and saves it in `base-sha`. `PSTACK_SYNC_STATE_DIR` overrides the default `~/.local/state/pstack-sync` directory. The directory contains `sync.log` and an `attempt-*` directory for each run. An attempt that invokes Claude retains `repo/`, `base-sha`, `prompt.txt`, `upstream-sha`, and `claude.log`.

The local runner records the user's explicit authorization to bypass no-mistakes only to publish that attempt's sync branch and create its draft PR. This exception applies only to that runner's publication in step 10. All local checks remain required. It does not authorize marking the PR ready, merging, pushing to `main`, or force-pushing. The Action and other publication routes keep their existing gate requirements.

Claude's exit code alone does not establish success. The runner requires clean committed work, the intended upstream SHA in the commit, and a live open draft PR to `main`. The PR must belong to this repository and match the attempt's branch and commit SHA. A failure after Claude starts retains the clone and exits nonzero. Unchanged-upstream skips, open-PR skips, and blocks caused by a prior unfinished attempt remove only the new untouched clone and retain the attempt directory. An unfinished attempt blocks another Claude run after the unchanged-upstream and open-PR checks. To recover, inspect `sync.log`, resume the retained `repo/` using `prompt.txt`, and resolve its work. Then move the whole resolved attempt outside the state directory before retrying. Keep that copy until its work is safe. Successful attempts remain retained with a `complete` file containing the verified PR URL. Harmless skips also have a `complete` file that records their reason.

Before checking the PR, the runner independently reads the committed promise ledgers at the pinned initial commit and candidate head. Missing or malformed ledger data blocks completion. It takes live owner paths from both ledgers and compares changed paths without rename detection. A changed or deleted owner still triggers the check after its promise is removed. A changed live owner requires an added or updated `.md` file under `evals/promises/results/` with nonempty committed contents. An unchanged report, a mode-only change, or a deleted report does not qualify. When no live owner changes, the runner requires no new report. A missing-report refusal names the changed promises and owners, retains the work, and leaves the attempt incomplete. This check proves that the sync committed a report. Reviewers still assess the report's truth, case coverage, and upstream prose fidelity. The check does not establish that every case passed.
